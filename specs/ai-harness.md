## 1. 한 줄로

**AI 도구는 모델 혼자가 아니라 「모델 + 도구를 쥐여 주는 바깥 층(하네스)」 이에요. 이 층을 내 작업에 맞게 꾸리는 법을 배워요.**

- 공식 문서의 말: 「모델은 생각하고(reason), 도구는 행동한다(act). Claude Code 는 모델을 둘러싼 층으로 도구를 주고 모델이 보는 맥락(context)을 관리한다. 이 둘러싼 층을 **agentic harness(에이전트 하네스)** 라고 부른다.」
- 챕터 1 ~ 3 은 「AI 에게 말로 잘 시키고, 결과를 검증하고, 책임지는」 법이에요. 챕터 4 는 **말이 아니라 환경으로** AI 가 잘 일하게 만드는 법이에요: 지침 파일 · 기록 · 검사(훅) · 권한 · 여럿에게 맡기기.
- 이 저장소가 실제로 쓰는 방식이 바로 하네스예요(`CLAUDE.md` · `HANDOFF.md` · `LESSON.md` · 검사 도구 · Stop 훅). 예제 이야기는 여기서 가져와요.

## 3. 말(용어) — 공식 문서에서 확인한 것만

출처는 모두 Claude Code 공식 문서(`https://code.claude.com/docs/en/…`)이고 11/9 에 직접 읽어 확인했어요. **이 표에 없는 사실은 레슨에 쓰지 않아요.** 다른 도구(Cursor · Copilot 등)의 파일 이름 · 화면은 확인하지 못해서 쓰지 않아요. 「도구마다 이름이 달라요」 까지만.

|---|---|

### 쪽 구성 (담당은 이 틀에서 시작해, 더 나은 순서가 있으면 바꿔도 돼요)

**Z13 하네스: 모델 + 도구**
- 0. 모델은 글을 만들 뿐이에요(F3) — 도구가 있어야 파일을 읽고 고쳐요. 이 둘러싼 층이 하네스(F1). 비유로 시작.
- 1. 한 바퀴 — 모으기 → 행동 → 확인(F2). 가짜 모델(정해진 대본)로 `run_agent` 한 바퀴.
- 2. 도구는 하네스가 실행해요 — 모델은 「이 도구를 이렇게 불러 줘」 라고 **요청**만 하고, 하네스가 실행해 결과를 되돌려줘요. 모르는 도구 이름이 오면 에러를 결과로 돌려줘요.
- 3. 멈추는 법과 기록 — 끝났다는 신호 · 최대 단계 수 · 단계마다 로그 한 줄.

**Z14 지침 파일**
- 0. 새 대화는 빈 머리(F4). 어제 한 말을 몰라요 → 파일로 이어요.
- 1. 지침 파일이란(F5 · F6). 맨 앞에 붙는다는 걸 `build_messages` 로 직접 봐요.
- 2. 무엇을 쓰고 안 쓰나(F7) — 쓸 것: 검사 · 실행 명령, 하지 말 것, 이름 규칙. 안 쓸 것: 길고 뻔한 설명, **비밀 값**(Z9).
- 3. 지침은 권고예요(F8) — `lint_instructions` 로 점검하고, 「꼭」 은 다음 레슨(Z16)으로.

**Z15 기록 남기기**
- 0. 대화는 사라져요(F4) → 인수인계 문서: 지금 상태 · 다음 할 일 · 막힌 것.
- 1. 실패 기록: 무슨 일 · 진짜 원인 · 다시 안 생기게 · 막는 장치(검사냐 규칙이냐). 규칙뿐인 기록이 두 번이면 검사로(이 저장소의 약속).
- 2. 문서의 숫자는 데이터에서 — `check_doc` 가 문서의 「지금 v…」 를 코드의 버전과 맞춰 봐요.
- 3. 공개 문서에 쓰면 안 되는 것(비밀 · 개인정보 · 남의 말을 그대로 옮기기) — `scrub`(Z9 연결).

**Z16 규칙보다 검사: 훅**
- 0. 권고 vs 결정적(F9 · F10). 표.
- 1. 훅이란(F12 · F13) — 정해진 때 내 스크립트가 돌고, 입력은 JSON, 결과는 종료 코드. `run_hook` 으로 흉내.
- 2. 막기 ① 위험한 명령(F14 · F15) — `pre_tool_hook`.
- 3. 막기 ② 멈추기 전에 확인(F16) — `stop_hook`(한국어 없이 영어로만 쓴 답 막기, `stop_hook_active` 로 무한 반복 막기). 이 저장소의 실제 훅 이야기.

**Z17 권한과 되돌리기**
- 0. 도구마다 허락이 달라요 — 읽기만 / 쓰기 / 실행. 허락 · 묻기 · 막기(allow · ask · deny).
- 1. 규칙 모양 `Bash(git *)` 와 평가 순서(F17 · F18) — `decide` 를 한 단계씩.
- 2. 최소 권한 — 필요한 것만 열고, 되돌릴 수 없는 것(`rm -rf`, `git push --force`, 비밀 파일 읽기)은 묻거나 막아요.
- 3. 되돌릴 수 있게 — 맡기기 전에 커밋(Z12 링크).

**Z18 여럿에게 맡기기**
- 0. 서브에이전트(F19) — 별도 대화창. 언제 맡기나.
- 1. 나눠 주기 — 담당 범위가 겹치면 합칠 때 부딪혀요. `find_overlap`.
- 2. 보고는 주장이에요(F11) — 몇 곳은 데이터로 직접 대조. `verify_reports`.
- 3. 합친 뒤 전체 검사 — 각자 통과해도 합치면 깨질 수 있어요.

## 5. 「만들어 보기」 설계

- 레슨마다 문제 **3 ~ 4개**(기존 Z 레슨과 같게), 보스 ZB4 는 **6 ~ 7개**(`check_book` ⑫ 는 보스에 5 ~ 10개를 요구하고, 보스의 칩이 챕터 4 의 레슨 Z13 ~ Z18 을 **모두 한 번 이상** 가리켜야 해요).
- 문제는 거의 전부 **입력을 받아 출력하는 파이썬**(`io` 로 자동 검사)으로, 가짜 모델 · 가짜 입력으로 해요. 인터넷 · 실제 AI 호출은 필요 없어요.
- 보스에는 내 PC 에서 하는 것(내 프로젝트에 지침 파일 만들기 등)을 `noRun` + 「확인할 것」(☐)으로 하나 넣어요. 도구는 내가 쓰는 AI 도구 아무거나예요.
- 문제 글은 기존 AI 협업 문제처럼 「레슨에서 만든 함수에 규칙을 더하는」 모양이 좋아요(예: Z12 의 `precheck` 에 규칙을 더하는 문제).
- 「필요한 문법」 칩은 실제 코드 모양 + 그 레슨의 쪽 링크 + 설명. 칩에 문장이 여럿이면 `\n` 으로(공백 두 칸으로 잇지 마요).

## 6. 쓰지 않을 것

- 도구 설치 · 로그인 · 가격 · 화면 메뉴 이름. (확인 못 하면 틀려요.)
- 3절 표에 없는 Claude Code 기능(스킬 · MCP · 플러그인 · 모드 등)을 사실처럼 쓰는 것. 이름만 한 줄 소개하려면 3절에 사실을 먼저 더해요.
- 「AI 가 반드시 …해요」 같은 단정. 지침은 권고이고 모델은 안 따를 수 있어요(F8).
- 실제 비밀 값 · 사용자 채팅 인용.

## 7. 화면 · 데이터 규칙 (기존 AI 협업과 같게)

- 레슨 데이터: `courses/ai/content.js` 의 `LESSONS` 에 `{id, ch:4, n, title, mode:'text', tutorSummary, terms, pages:[{title, html, example:{code}}], summary}`. 문제: `courses/ai/book.js` 의 `BOOK.tasks`. 본보기는 **Z12**(레슨)와 `BOOK.tasks.Z12`(문제).
- 해요체. 「이 앱」 · 「채점」 · 「입력창」 · 「종이에 적어」 · 「약 N분」 금지. 새 말은 설명 먼저, 새 문법은 무엇을 돌려주나 · 차이 · 경계 · 실제 결과까지(`LESSON.md` U8).
- 이 교과서의 대상은 **챕터 4(파이썬 교과서)까지 아는 사람**이라, 예제는 함수 · 리스트 · 딕셔너리 · 문자열 · `re` · `json` 정도만 써요. 클래스 · 제너레이터는 쓰지 않아요.
- 예제의 가짜 모델은 「정해진 대본을 차례로 돌려주는 함수」 로 만들어요(진짜 AI 처럼 보이게 꾸미지 않아요). 레슨 글에 「진짜 모델은 이렇게 정해져 있지 않아요」 를 한 번 밝혀요.
- 다른 교과서로 보내는 링크는 기존 모양(`<a href="../terminal-git/#lesson/T6" target="_blank" rel="noopener">…</a>`)을 따라요.
