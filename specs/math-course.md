## 1. 정해진 것

- **누가 읽나**: 이 사이트의 사용자 한 명이에요(성인 입문자 — [`site-intent.md`](site-intent.md) 1절). 중고등 수학을 처음부터 다시 배워요.
- **범위와 순서**(D35): 중고등 수학을 처음부터. 순서의 뼈대는 2022 개정 교육과정이고, 먼저 중1 범위 35 레슨만 만들어요.
- **수학만**(D36): 파이썬 코드 · VS Code 과제를 넣지 않아요. 연습은 손으로 풀고 답을 확인해요.
- **레슨 제목은 개념 이름**(LESSON.md U15): 「약수와 배수」 처럼 써요. 한 줄 설명(「나누어떨어진다는 뜻」)은 목차에서 제목 아래에 같이 보여요.
- **레슨 짜임**: 왜 배우나(장면 하나) → 개념을 한 단계씩 → 예제 풀이(단계를 빼지 않음) → 연습 문제 → 자주 하는 실수.
- **채점 없음**([`site-intent.md`](site-intent.md) 1절 · 3절 「채점 없음」): 답을 쳐 넣으면 맞는지 알려 주는 칸, 푼 문제에 붙는 표시는 만들지 않아요. 답과 풀이를 펴 보고 스스로 맞춰 봐요. 읽은 레슨 표시는 다른 교과서와 같아요.
- **만드는 순서**: 한 챕터씩이에요. 챕터 1을 만들어 사용자가 읽어 보고 이해되는지 확인한 뒤 다음 챕터로 가요.

왜 새로 만드나: 옛 수학 교과서(45 레슨)는 내용이 이해되지 않고 목차 제목이 돌려 말해서 v2.48.0 에 전부 지웠어요(D34). 그래서 이번 기준은 셋이에요 — 목차만 읽어도 무엇을 배우는지 알 것, 한 번에 한 가지만 말할 것, 풀이 단계를 건너뛰지 않을 것.

## 2. 레슨 한 편의 재료와 쓰기 규칙

시안의 레슨 1을 쓰면서 정한 모양이에요. 세 가지 쪽 짜임(3절)이 모두 같은 재료를 써요.

| 재료 | 들어가는 것 | 레슨 1 에서 |
|---|---|---|
| 설명 덩어리 | 제목(「개념 이름: 한 줄 뜻」) · 글 · 식 · 그림. 첫 덩어리는 장면으로 시작해요 | 4개 |
| 예제 | 문제 → 이끄는 말 → 풀이 줄(번호를 붙이고 빼지 않음) → 덧붙임(왜 그렇게 해도 되나) → 그림 → 답 | 3개 |
| 연습 문제 | 제목 · 문제 · 답 · 풀이 줄 · 막히면 다시 볼 곳(설명 덩어리나 예제 하나) | 6개(마지막은 생활 장면 문제) |
| 자주 하는 실수 | 틀린 예 · 바른 예 · 도움말 한 줄 | 3개 |

쓰기 규칙은 레슨 1 초안을 다른 에이전트가 따로 읽고 짚은 것에서 나왔어요(6절). 다음 레슨도 이 규칙으로 써요.

1. 새 낱말은 처음 쓰는 자리에서 뜻을 매겨요. 교과서 밖에서 안 쓰는 말이면(「짝」) 이 교과서에서만 부르는 이름이라고 밝혀요.
2. 같은 사실을 다르게 쓴 식 사이에는 다리를 놓아요. 예: 나눗셈식 12 ÷ 3 = 4, 나머지 0 과 곱셈식 12 = 3 × 4.
3. 같은 종류의 식은 늘 같은 꼴로 써요. 나눗셈은 「a ÷ b = 몫, 나머지 r」 이고, 나머지가 0이어도 적어요.
4. 풀이에서 멈추거나 건너뛰는 자리에는 까닭을 적어요. 규칙은 뒤에 나오는 경우까지 덮는 한 문장으로 정리해요.
5. 예제가 다루지 않은 꼴을 연습 문제에 내지 않아요. 연습에 36 = 6 × 6 이 나오니, 예제 2(16 = 4 × 4)가 있어요.
6. 연습 문제의 풀이는 예제와 같은 차례 · 같은 말로 써요.
7. 맞는 답이 여러 꼴이면 다 적어요. 예: 45 ÷ 15 = 3, 나머지 0 또는 45 = 15 × 3.
8. 경계가 되는 경우를 본문에서 말해요. 예: 1의 약수, 자기보다 큰 수로 나누기.
9. 문제 글은 한 가지로만 읽히게 써요.
10. 계산 결과는 손으로 적지 않아요. 몫 · 나머지 · 짝은 코드가 계산해 넣고, 글 속의 식은 검사가 다시 계산해요(4절 `check_math.mjs`).
11. 식은 줄 중간에서 끊기지 않게 한 덩어리로 묶어요(시안의 `mx-m`).
12. 그림마다 글로 된 설명(`aria-label`)을 달아요. 그림을 못 봐도 같은 내용을 읽을 수 있어야 해요.

## 3. 화면 시안 — 고를 것 넷

같은 레슨(레슨 1 「약수와 배수」)을 실제 사이트의 CSS(`core/ui.css`)와 교과서 화면의 틀로 그렸어요. 길이는 모두 `measure.mjs` 가 잰 값이에요(4절). 「장」 은 화면 높이의 몇 배인지예요 — 폰은 390 × 844, PC 는 1440 × 900.

### 3-1. 레슨 쪽 짜임

| 시안 | 어떻게 읽나 | 폰에서의 길이 | PC 에서의 길이 |
|---|---|---|---|
| **A · 쪽 넘기기** | 지금 교과서와 같은 틀이에요. 번호 탭(1 ~ 7)과 「✏️ 연습 문제」 탭을 눌러 한 쪽에 한 덩어리씩 봐요. 연습 문제 쪽 끝에 자주 하는 실수가 있어요. PC 는 ← → 키로도 넘겨요 | 쪽마다 1.2 ~ 2.0장 · 연습 문제 쪽 3.6 ~ 3.9장 | 쪽마다 1.0 ~ 1.4장 · 연습 문제 쪽 2.9장 |
| **B · 한 장 스크롤** | 레슨 전체가 한 쪽이에요. 위의 차례 줄(왜 배우나 · 개념 · 예제 · 연습 · 실수)이 따라 내려오며 지금 자리를 알려 줘요. PC 는 왼쪽에 「이 레슨의 차례」 가 붙어요 | 10.8장 | 7.7장 |
| **C · 단계 카드** | 「다음 단계」 를 누르면 카드가 하나씩 아래에 이어 붙어요(9단계 = 설명 4 · 예제 3 · 연습 문제 · 자주 하는 실수). 예제 풀이도 「풀이 다음 줄 보기」 로 한 줄씩 펴요. PC 는 Enter 키로도 넘겨요 | 처음 1.6장 → 다 펴면 11.5장 | 처음 1.1장 → 다 펴면 7.9장 |

- A 는 지금 교과서 화면 코드를 거의 그대로 써서 가장 빨리 만들어요. 대신 앞 쪽을 다시 보려면 탭을 오가야 해요. 연습 문제의 「막히면 다시 보기」 를 누르면 그 쪽으로 갔다가 「돌아가기」 로 돌아오게 해 두었어요.
- B 는 앞뒤를 오가며 찾아보기에 좋아요. 대신 폰에서 길고, 예제 풀이가 처음부터 다 보여요.
- C 는 한 번에 한 가지만 보이고 앞 단계가 위에 남아요. 예제에서 다음 줄을 먼저 생각해 본 뒤 펼 수 있어요. 대신 새로 짤 화면 코드가 가장 많고, 다시 들어왔을 때 어디까지 펴 둘지를 정해야 해요(5절).

### 3-2. 연습 문제 답 확인

손으로 푼 다음 답을 어떻게 확인하느냐예요. 세 가지 모두 문제마다 「막히면 다시 보기」 가 있어요.

| 시안 | 어떻게 확인하나 | 연습 문제 쪽 길이(폰 · 답을 접은 채) |
|---|---|---|
| **가 · 한꺼번에** | 「답과 풀이 보기」 하나를 펴면 답과 풀이가 같이 나와요. 지금 교과서의 「예시 답 보기」 와 같은 방식이에요 | 3.6장 |
| **나 · 답 먼저, 풀이 따로** | 「답만 보기」 로 답만 맞춰 보고, 틀렸을 때 「풀이 보기」 를 눌러요 | 3.6장 |
| **다 · 풀이 한 줄씩** | 「답만 보기」 와 「풀이 한 줄 보기」 가 따로 있어요. 풀이는 「한 줄 더 보기」 로 막힌 데까지만 펴고 다음 줄은 직접 해 봐요. 「전부 보기」 · 「풀이 접기」 도 있어요 | 3.9장 |

### 3-6. 일부러 넣지 않은 것

- 답을 쳐 넣으면 맞는지 알려 주는 칸, 푼 문제 표시 · 점수: 사이트가 채점으로 붙잡지 않는다는 원칙이에요(1절).

### 3-7. 시안을 확인한 방법

- 폰 390 과 PC 1440 을 같이 찍었어요. 밝은 테마 · 글자 「아주 크게」 · 좁은 폰(320)도 봤어요.


- 필요한 것: Playwright 와 한글 글꼴(이 환경에서는 `fonts-noto-cjk` 를 설치했어요). 글꼴이 다르면 길이가 조금 달라져요.
- 시안 파일의 주소 값: `s=lesson|toc` · `v=A|B|C`(쪽 짜임) · `k=1|2|3`(답 확인 가 · 나 · 다) · `t=1|2`(목차 ㄱ · ㄴ) · `p`(A 의 쪽) · `step`(C 에서 편 카드 수) · `lines`(C 에서 편 예제 풀이 줄 수) · `bare=1`(시안 고르기 줄 숨김).
- 3절의 숫자를 고칠 때는 `measure.mjs` 출력을 그대로 옮겨요(LESSON.md R10).
- **교과서를 만들고 나면 이 폴더를 지워요.** 그때 `check_math.mjs` 는 `tools/` 의 검사로 옮겨요(5절).

## 5. 만들 때 메모

고른 뒤 챕터 1을 만들 때 볼 것이에요.

### 화면

- A 를 고르면 교과서 화면(`core/ui-views-book.js`)의 쪽 탭과 과제 목록(`bk-tasks` · `bk-ans`)을 거의 그대로 써요. B · C 와 답 확인 나 · 다, 목차 ㄴ 은 새 화면 코드가 필요해요. 시안의 `src/app.js` 에서 고른 것만 옮겨요.

### 데이터와 id

- 레슨 id 는 밑줄 없는 `M0` · `M1` … 꼴로 해요. 사용자 브라우저에는 옛 수학 기록(`M1_mod` 처럼 밑줄 있는 id)이 남아 있어요.
- `core/config.js` 의 `COURSE_ID_PATTERNS.math` 는 지금 옛 꼴(`^M\d+_`)이에요. 새 꼴로 바꾸면 허브의 읽은 수(`Hub.bookProgress`)가 규칙에 맞는 id 만 세므로 옛 기록이 새 진도에 섞이지 않아요.
- 바꾸면 옛 id 는 어느 코스 규칙에도 안 맞게 돼요. `Store.untangle` 은 주인 없는 id 를 건드리지 않아요. 옛 기기 연동 형식을 풀 때(`core/sync.js`)는 주인 없는 id 가 파이썬 조각으로 들어가는데, 파이썬의 읽은 수도 자기 규칙에 맞는 id 만 세요. 만들 때 실제 기록으로 한 번 확인해요.
- 새 id(`M0` · `M1` · `M34`)는 지금 다른 코스의 규칙과 겹치지 않아요(11/15 확인). `validate_content` 가 겹침을 검사해요.

## 6. 레슨 1 「약수와 배수」 초안

시안에 넣으려고 쓴 초안이에요. 전체 글은 `specs/ref/math-mock/src/lesson.js` 에 있고, `node specs/ref/math-mock/dump_lesson.mjs` 로 읽기 좋게 뽑아요. 여기에는 짜임만 적어요.

| 차례 | 종류 | 제목 |
|---|---|---|
| 1 | 설명(장면) | 나누어떨어진다: 나머지가 0 — 귤 12개를 봉지에 똑같이 나눠 담기 |
| 2 | 설명 | 약수: 나누어떨어지게 하는 수 |
| 3 | 설명 | 배수: 몇 배 한 수 |
| 4 | 설명 | 약수와 배수의 관계: 12 = 3 × 4 |
| 5 | 예제 1 | 18의 약수 모두 구하기 — 곱해서 18이 되는 짝을 작은 수부터 찾고, 어디서 멈추는지 |
| 6 | 예제 2 | 16의 약수 — 짝의 두 수가 같을 때 |
| 7 | 예제 3 | 배수인지 확인하기 — 56과 58은 7의 배수인가 |
| 8 | 연습 문제 6개 | 약수 모두 구하기 · 약수가 둘뿐인 수 · 배수 고르기 · 약수의 개수 · 약수인가 배수인가 · 쿠키 나눠 담기(생활 장면) |
| 9 | 자주 하는 실수 3개 | 1과 자기 자신을 빼먹어요 · 약수와 배수를 거꾸로 말해요 · 짝의 두 수가 같을 때 두 번 적어요 |

- 그림은 일곱 개예요: 점 묶음 둘(12개를 3개씩 · 5개씩) · 12를 1 ~ 12로 나눠 본 표 · 수직선에서 3씩 뛰기 · 12 = 3 × 4 관계 그림 · 약수 짝 그림 둘(18 · 16).
- 검수: 쓴 사람과 다른 에이전트가 처음 배우는 사람의 눈으로 따로 읽었어요. 수학이 틀린 곳은 없었고, 막히거나 헷갈릴 수 있다고 짚은 16곳을 모두 고쳤어요(2절의 쓰기 규칙이 여기서 나왔어요). 그 뒤 예제 2와 연습 문제 하나를 더했고, 식은 `check_math.mjs` 로 다시 계산했어요.
- 이 초안은 「약수가 둘뿐인 수」(7)를 연습 문제에 넣어 레슨 2 「소수와 합성수」 로 이어지게 했어요.
- 사용자가 아직 읽고 확인한 글이 아니에요. 챕터 1을 만들 때 다듬어요.
