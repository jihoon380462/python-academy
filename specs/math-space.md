## 14. 수학 공간 — 프로그래머 수학 (별도 구역)

코스 목록과 분리된 **두 번째 공간**이다. 허브의 코스 카드 아래에 "수학 공간" 구역(카드 1장, `CONFIG.COURSES`에 `space:true`)을 두고, 들어가면 선형 챕터 지도가 아니라 **지식 지도**(주제 노드 + 선수 관계 선)로 보여준다. 범위는 고등학교 수학 전체 + 대학 1학년 맛보기(미적분·선형대수·확률분포·증명)이고, 전부 "프로그래밍에서 어디에 쓰나"로 들어간다. 무료 교육 원칙(DESIGN.md 14절)을 따른다: 학습자 비용 0, 브라우저 안에서 전부 동작.

**대원칙: 그림이 먼저, 식은 나중, 손계산은 없다**

- 모든 주제의 첫 화면은 글이 아니라 **만질 수 있는 그림**이다. 슬라이더를 밀거나 점을 끌면 그림이 즉시 바뀐다. 설명은 그림 아래 3줄 이내.
- 수식은 그림을 만지고 난 뒤에 나온다. 수식의 각 항에 마우스를 올리면 그림의 해당 부분이 같은 색으로 빛난다(수식 ↔ 그림 ↔ 코드 세 개가 같은 색 체계).
- 계산은 파이썬이 한다. 사용자는 코드를 고치고 그림이 어떻게 변하는지 본다. 알고리즘 코스의 시각화 엔진(`core/visualize.js`)을 확장해 쓴다.
- 주제 하나 = 10~20분. 구성은 고정: ① 어디에 쓰나(게임·데이터·알고리즘 중 하나의 실제 장면 한 컷) → ② 만지는 그림 → ③ 그림에서 규칙 발견(질문 2~3개) → ④ 식과 코드 대응 → ⑤ 문제 3~5개.

**시각화 종류** (`visualize.js`에 추가, 전부 캔버스·터치 대응)

**문제 유형** (전부 그림이 같이 뜨고, 기존 유형 중 퀴즈·코드 작성도 사용)

- **탐구 퀴즈**: 슬라이더를 움직여 보고 답한다("a를 크게 하면 그래프는?"). 슬라이더를 실제로 움직여야 보기가 활성화된다.
- **그림 맞추기**: 목표 그림을 보고 파라미터(또는 코드 한 줄)를 맞춰 같은 그림을 만든다. 오차 허용 채점.
- **식↔그래프 짝짓기**: 식 4개와 그래프 4개를 연결.
- **숫자 답**: 코드로 계산해 답을 넣는다. 오차 허용.
- **시뮬레이션 검증**: "10만 번 돌려서 이론값과 1% 안에 들어오게 해라." 히스토그램이 쌓이는 걸 보며 통과.
- **식→코드 번역**: Σ·점화식·벡터 식을 파이썬 함수로. Parsons 변형 포함.
- **구현 문제**: `dot(a,b)`, `rotate(p,θ)`, `mean/var`, `numerical_derivative(f,x)` 같은 함수를 직접 써서 그림이 맞게.

**14-1. 수학이 싫었던 사람을 위한 진입 설계**

- 수학 탭의 첫 화면은 지식 지도가 아니라 **"이미 쓰고 있는 수학" 카드 3장**이다: 사용자가 풀어 둔 파이썬·알고리즘 문제에서 "이 코드의 `%`가 사실 나머지 연산", "이 `range`가 수열", "이 `if a > b`가 명제" 식으로 집어주고, 누르면 그 노드로 간다. 지도는 그 아래. "수학을 새로 배운다"가 아니라 "이미 하던 걸 이름 붙인다"로 시작한다.
- 노드 제목은 학교식 이름 대신 **질문형**: "기울기" 대신 "얼마나 빨리 변하나", "내적" 대신 "같은 방향을 보고 있나", "정규분포" 대신 "왜 평균 근처에 몰리나". 학교식 이름은 부제로, 그림을 다 만진 뒤 ④단계에서 붙인다.
- 노드마다 난이도 점 1~3개와 필요한 선수 노드 표시. 고등학교 범위 표기(고1·고2)는 설정에서 끌 수 있다(학교 기억이 부담인 사람용).
- 계산 실수로 틀리는 일이 없게: 숫자 답 문제는 입력칸 옆에 항상 "코드로 계산하기" 미니 에디터가 붙어 있고, 거기서 `print`한 값을 한 번에 답칸으로 보내는 버튼이 있다.

**14-2. 세 표현 동기화(그림 ↔ 식 ↔ 코드)의 구체 메커니즘**

- 노드 데이터는 **파라미터 목록**을 중심으로 묶인다: `params: [{id:'a', label:'기울기', min:-3, max:3, step:0.1, default:1}, ...]`. 슬라이더 하나 = 파라미터 하나 = 코드의 변수 하나(`a = 1`). 슬라이더를 밀면 코드의 그 줄이 바뀌고 다시 실행되어 그림이 갱신된다(v2.2.4의 `example.slider` 확장). 코드를 직접 고쳐도 슬라이더가 따라온다.
- 색 연결은 **부분 id**로: 수식은 `latex`에 `\class{p-a}{a}`처럼 KaTeX 클래스를 심고, 그림 요소는 `figure.parts: {'p-a': '기울기 화살표'}`, 코드는 토큰 `a`에 같은 id. 셋 중 어느 하나에 마우스·터치를 올리면 세 곳이 같은 색으로 빛나고 나머지는 흐려진다. 모바일은 탭으로 고정, 다시 탭하면 해제.
- 색은 파라미터당 1색, 최대 5색(팔레트 고정). 색각 보정: 색과 함께 **모양**(실선/점선/굵기)과 라벨을 병행해 색만으로 구분하지 않는다(v2.2.9 접근성 원칙).
- 그림 설계 기준: 항상 격자·축·단위 표시, 애니메이션 300ms 이내, 한 화면에 조작 요소 최대 3개(슬라이더 2 + 드래그 1). 세로 비율은 모바일에서 그림이 화면 높이의 45%를 넘지 않게.

**14-3. 수학 노드 콘텐츠 스키마** (`courses/math/content.js`, 검증 스크립트가 검사)

```
{ id:'A4_slope', area:4, title:'얼마나 빨리 변하나', subtitle:'기울기와 변화율', level:'고2', stars:2,
  prereq:['A4_linear'], uses:['game','data'],
  scene:{ text:'캐릭터가 1초에 몇 칸 움직이나 = 속도', visualize:'plot', ... },
  params:[{id:'a',label:'기울기',min:-3,max:3,step:0.1,default:1}],
  figure:{ kind:'plot', fn:'a*x+1', parts:{'p-a':'기울기 화살표'}, observe:['a를 음수로 하면?', 'a=0이면?'] },
  formula:[{ latex:'y = \\class{p-a}{a}x + 1', note:'a가 1 커지면 x 한 칸에 y가 한 칸 더' }],
  code:'a = 1\ndef f(x):\n    return a*x + 1',
  problems:['A4_slope_q1', ...], vary:{a:[-2,2]} }
```

- `scene.visualize`는 필수(첫 화면이 그림). `params`는 1~3개. `observe` 질문은 2~3개이며 각각 탐구 퀴즈 하나와 짝.
- 문제 스키마에 `answer:{value, tol, unit}`(숫자 답, 허용 오차·단위), `match:{params, tol}`(그림 맞추기), `sim:{seed, trials, target, tol}`(시뮬레이션)를 추가.
- 단위 규칙: 각도는 기본 라디안, 화면 표시는 도(°) 토글 가능. 채점은 둘 다 받고 단위 착오면 "라디안으로 넣었나요?" 규칙 설명.

**14-4. 숙련도와 복습**

- 노드 숙련도 3단계 링: ① 탐구(그림 만지고 관찰 질문 통과) ② 풀이(문제 전부 클리어) ③ 유지(복습 큐에서 변형 문제 2회 통과). 지식 지도의 노드는 링이 찰수록 밝아지고 영역이 색칠된다.
- 복습 변형은 기존 `vary` 필드로 파라미터를 바꿔 출제(파이썬 코스 규칙 그대로). 그림 맞추기는 목표 파라미터가 매번 다르다.
- 영역을 전부 ③까지 채우면 영역 뱃지 + 마스코트 박사모 색 변화(동→은→금).

**14-5. 모바일**

- 슬라이더 손잡이 44px 이상, 그림 아래 가로 배치. 드래그 가능한 점은 반경 22px의 투명 터치 영역.
- 그림은 가로 꽉 채우고, 식·코드는 탭으로 전환(그림은 항상 위에 고정). 세 표현 동기화는 "식 탭"에서 항을 탭하면 그림이 반응하는 방식.
- 핀치 줌은 그림 안에서만, 페이지 스크롤과 충돌하지 않게 두 손가락만 그림이 가져간다.
