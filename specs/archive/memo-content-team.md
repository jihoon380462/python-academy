## 4. 운영 규칙끼리 부딪히는 곳 (팀 통합 때 정리)

1. **`CHANGELOG.md` `## 미배포` 충돌이 PR 마다 남** — 모두 절 **맨 위**에 한 줄을 넣어서, 먼저 병합된 PR 뒤로는 전부 충돌. 오늘 C6↔C7, C7↔C8, C10↔(#23·#25·#26) 에서 반복. 임시로 C8·C10 은 절 **끝**에 넣어 피함.
   - 제안: PR 은 `changelog.d/<브랜치>.md` 파일 하나만 추가하고, 릴리스 커밋이 모아서 CHANGELOG 로 옮기기. 또는 「미배포 절 끝에 추가」로 규칙 통일.
2. **`docs/QA.md` 도 같은 문제** — 팀마다 같은 기준 줄 위에 절을 끼워 넣어 충돌(C7 rebase 때 직접 해결). 제안: 절마다 파일 분리(`qa/<날짜-팀>.md`) 또는 「맨 아래에 추가」.
3. **지시서끼리 모순**: `content-team.md` 3절 「과제를 끝내면 HANDOFF "다음 후보"의 콘텐츠 줄을 갱신」 ↔ workflow 8절 「HANDOFF 상태판은 손대지 않는다」. 오늘은 8절을 따름(HANDOFF 안 고침, PR 본문에 적음).
4. **`gh pr create` 가 Claude 세션에서 안 됨** — GraphQL 이 막혀 `HTTP 403`. workflow 8절 3항 대신 REST 로:
   `gh api repos/jihoon380462/python-academy/pulls -f title=… -f head=<브랜치> -f base=main -F body=@본문.md`
5. 「파일 끝에 추가」 규칙이 표시 순서와 묶여 있음(3절 #1). 순서가 중요한 콘텐츠는 이 규칙으로 못 넣음.
