## 4. 릴리스 절차

- **main 보호 규칙 때문에 릴리스 당번이 직접 푸시 못 함** → `release/vX` 브랜치 PR + 사용자 Merge 클릭(사용자 왕복 1번). Merge 방식은 반드시 **「병합 커밋 만들기」**(squash 면 포함된 PR 들이 열린 채로 남음) — 매번 안내함.
- **릴리스 PR 을 Merge 하기 전에 새 초록 PR 이 쌓임** → v2.3.10 은 릴리스 PR #24 를 다시 만들어(같은 브랜치 강제 푸시) 6개로 묶음. 릴리스 PR 을 연 뒤에는 새 PR 을 다음 릴리스로 미루는 게 깔끔.
- **릴리스 창(매일 18:00)보다 자주 배포**: 11/2 하루에 3번(사용자 요청). 통합 뒤 리듬을 다시 정하기.
- 각 PR 의 CI(`verify`)는 초록이어도 **합친 결과**는 따로 검사해야 함(실제로 합친 뒤 validate 규칙 두 개가 한 파일에서 충돌) — 4절 4단계 게이트를 꼭 병합본에서.

## 7. 작업 환경 메모 (다음 세션용)

- `gh` 는 REST 만 됨(GraphQL 막힘): `gh pr list` 대신 `gh api repos/jihoon380462/python-academy/pulls?state=open`, PR 만들기는 `gh api …/pulls -f title -f head -f base -F body=@파일`.

- npm 레지스트리·CDN 은 샌드박스에서 막힘 → Blockly 한국어 라벨 등은 브라우저 확인.
