# 사이트 의도 — QA·새 세션이 맨 먼저 읽을 것 (2026-11-06, v2.10.1 기준)

> 사용자 지시(11/6) 「QA 가 해당 사이트의 의도를 파악할 수 있게 문서 최신화 진행」. 이 파일은 **「무엇이 정상이고 무엇이 버그인가」의 기준**이다.
> 다른 문서(QA.md 옛 회전, QA-OPEN.md, specs/qa-team.md 의 옛 체크리스트, DESIGN.md 3~5절 XP·뱃지·블록)는 문제집 시절 기록이 섞여 있다. **서로 다르면 이 파일이 맞다.** 이 파일이 틀렸으면 고치고 `업데이트:` 줄을 바꾼다.
> 업데이트: 2026-11-06 · v2.14.0 (웹 교과서 — 코스 7개 전부 열림)

## 1. 누구를 위한 사이트인가

- **사용자 본인 한 명**이 쓰는 학습 사이트다(성인 입문자, D1). 사용자 말 그대로: 「어차피 나만 쓸 건데 억지로 붙잡으려고 할 필요 없잖아」.
- 목표는 **「완강하면 혼자서 만들 수 있게(create)」**. 따라 치기·반복(repeat)만으로는 안 된다는 게 사용자 판단이다 — 「학습은 repeat 만 있고, 완강을 해도 혼자서 create 는 전혀 못할 것 같다. 발상의 전환이 필요해」(11/6).
- 그래서 **게임 요소(XP·레벨·스트릭·뱃지·잠금·채점)로 붙잡지 않는다.** 읽고, 자기 컴퓨터의 진짜 도구로 만들어 보는 게 중심이다.
- 「**실전은 오픈북**」(D8): 문법·명령을 숨기거나 외우게 하지 않는다. 도감에서 찾아 쓰게 한다.

## 3. 교과서 코스에서 「정상」인 것 (버그로 적지 말 것)

- 채점·제출 버튼·XP·레벨·스트릭·콤보·뱃지 팝업이 **없다**. 레슨 잠금도 없다(아무 레슨이나 연다).
- 「만들어 보기」 문제는 **정답 확인을 사이트가 하지 않는다.** 사용자가 자기 도구에서 돌려 「출력 예」(파이썬) / 「이렇게 나오면 성공」(터미널)과 비교한다. 예시 답은 접혀 있다.
- 옛 주소 `#problem/L4P2` → 그 레슨의 「🛠 만들어 보기」 쪽으로 간다. 복습·타자 연습·도전·타임어택·종합 점검·모의고사 화면 → 목차로 간다.
- 설정에서 키보드·효과음·진동·하루 목표·게임 요소·전제 무시·온보딩 다시 보기·클로드 선생님 칸이 **숨겨져 있다**(v2.9.5).
- 닉네임·하루 목표를 묻는 온보딩이 없다.
- 「💡 더 알아보기」가 접혀 있지 않고 펼쳐져 있다(오픈북, v2.9.4).
- 터미널 교과서의 Git 레슨(T7~TB3) 1쪽·만들어 보기·Git 챕터 목차 위의 「⚠ 레슨 6 설정 필수」 경고 상자(사용자 11/6 「레슨 6번은 설정을 해야 한다고 강조해」) — 여러 번 보이는 게 **의도**다. v2.12.2 부터 모든 교과서에 같은 「⚠ 먼저 꼭!」 상자(파이썬: 시작하기 1~3 · 터미널: 시작하기 1~3 · Vim: 시작하기 1~2, 레슨 6 _vimrc, 파이썬·Git 설치)가 있다 — 사용자 「필수 사항은 강조하고」. 새 교과서를 만들 때도 `BOOK.meta.prereq` 로 먼저 할 것을 단다.
- 터미널 결과 예의 `/c/Users/me` — `me` 는 사람마다 다른 Windows 사용자 이름이라 안내 문구가 붙는다.
- Vim 교과서의 「만들어 보기」 는 **준비 명령**(Ex 명령 한 줄: 📋 복사 → gVim 에서 `:` → Ctrl+R `+` → Enter)으로 `~/vim-study/파일` 을 처음 상태로 열고, 「다 하고 :w 하면 파일이 이렇게 돼요」(+ 파이썬이면 「F5 로 실행하면」)와 비교한다. 예시 답 키 표기 `<Esc>` `<Enter>` `<C-n>` `<BS>`. 플러그인 설치·대화형(gc 확인·F6 입력) 문제는 사이트가 검사하지 않는다(정상).

## 5. 교과서의 짜임 (어디를 보면 되나)

- 첫 화면(코스 홈) = **🛠 시작하기**(설치·도구 연결, 처음 한 번) + **📚 도감** 카드 + 챕터별 레슨 목록.
- 레슨 = 설명 쪽들(각 쪽 아래 📋 복사되는 예제) + 맨 끝 탭 **「🛠 만들어 보기」**(문장으로 된 문제 · 필요한 문법/명령 · 입력·출력 예 · 접힌 예시 답). 터미널은 문제마다 **준비 명령**(연습 폴더를 처음 상태로 만듦)과 **확인 명령**이 더 있다.
- 보스(챕터 끝) = 「만들어 보기: …」 — 그 챕터를 묶는 큰 문제 + 🏠 생활형 문제.
- 데이터: `courses/<코스>/book.js`(전역 `BOOK`: meta·setup·titles·pages·lessonPages·builtins·tasks). 화면: `core/ui-views-book.js`(모든 교과서 코스 공용). 머리 주석에 필드 설명이 있다.

## 6. 허브(메인화면, `index.html`)의 의도

- 구역: 「코스」(파이썬·알고리즘·터미널·SQL·웹) + **「공용」**(코스 순서와 무관 — 수학 공간·Vim 에디터, 사용자 11/6 「공간을 공용으로 변경」).
- 「오늘 뭐 할까」에 바로 답하는 화면. **▶ 이어서 버튼** = 마지막으로 보던 코스·레슨(교과서는 「○○ 교과서 이어서 읽기」, 아직 아무것도 안 봤으면 안 읽은 첫 레슨).
- 교과서 코스 카드 = 📖 읽은 레슨 n/m(레슨 끝까지 넘기면 읽음). 문제집 코스 카드 = n/N 문제.
- 「오늘」 숫자·복습 큐는 **문제집 코스(수학)만** 센다(v2.15.0 알고리즘도 교과서). 「오늘의 도전」은 없다(교과서에서 도전 화면이 없어짐).
- 허브는 코스의 book.js 를 읽지 않는다 → 카드 문구·레슨 수는 `core/config.js` 의 `COURSES`(`book:true`, `lessons`, `bookNote`)에 손으로 적고, `check_book` 이 레슨 수와 「가상·시뮬레이터」 같은 옛 문구를 검사한다.

## 7. 자동 검사 (QA 전에 먼저 돌리기)

```
node tools/validate_content.mjs && node tools/check_book.mjs && node tools/check_level.mjs --gate && node tools/check_nesting.mjs
node tools/extract.mjs tools/.out && python3 tools/run_solutions.py
node tools/test_shell.mjs && node tools/run_shell_solutions.mjs && python3 tools/run_sql_solutions.py
python3 tools/regress.py        # 화면 회귀(Playwright). 끝 줄 FAILS 0 이어야 함. 교과서 절: 「[파이썬 교과서 모드]」「[터미널·Git 교과서]」「[Vim 교과서]」
```

`check_book` 은 Vim 교과서의 예시 답 키를 **진짜 vim**(교과서의 기본 _vimrc 로)에 넣어 결과 파일·파이썬 실행 결과를 비교하고, 기본 _vimrc 가 에러 없이 읽히며 .py 에서 들여쓰기 설정이 켜지는지도 본다.

`check_book` 은 v2.15.2 부터 이것도 본다(사용자 「3, 4」 — 알고 교과서를 손으로 QA 하며 찾은 종류를 자동으로):
- ⑤ 레슨 본문의 「실행하면 <code>값</code>」 이 그 쪽 예제를 실제로 돌린 출력에 있는지(파이썬·알고리즘 python3, SQL SQLite). 파이썬 예제는 주장이 없어도 **전부** 돌려 에러가 나는지(일부러 에러를 보여 주는 쪽은 `BOOK.meta.exampleErrorsOk`).
- ⑥ 「필요한 문법」 코드 속 함수·메서드 이름이 링크된 쪽(제목·본문·예제)에 실제로 나오는지 — 안 나오면 다른 쪽을 가리키는 것.
- ⑦ 레슨 쪽에 예전 문제집 화면 말(이 앱·채점·입력창·슬라이더·XP·다음 줄 실행·파일 트리, 그림 없는 코스의 👀·👣)이 남았는지.
- ⑧ 터미널 교과서: 시작하기 → 레슨 순서로 예제를 **한 사람의 Git Bash 처럼 이어서**(폴더 위치가 다음 예제로 이어짐) 쳤을 때 「No such file」·「not a git repository」 가 나는지.

웹 교과서의 예시 답은 `python3 tools/run_web_solutions.py`(regress 단계)가 미리보기 iframe 에 넣어 「확인할 것」 전부 ✓ 인지 본다(fetch 는 mock, localStorage 는 메모리로 대신).
