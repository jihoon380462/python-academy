# 영어 단어장 — 설계와 지시서 (필수교양)

허브 맨 위 「필수교양」 묶음의 영어 단어장을 어떻게 만들었고, 무엇이 남았는지 적은 문서예요. 단어장 일을 이어받는 세션은 이 문서만 읽고 바로 시작할 수 있어야 해요.

- 처음 쓴 때: 2026-11-12 · v2.46.0 (뼈대와 코어를 만든 세션)
- 고친 때: 2026-11-12 · v2.46.1 (기초 덱의 파일 틀 도구 · 아는 단어 한꺼번에 넘기기 · 어려운 경우 본보기와 검수 절차) · v2.46.4 (어른 기준 · 속어 뜻) · v2.46.5 (속어 덱 W10 · 노트 대조 도구) · 그 뒤 문서만 (0절 상태 줄과 그 검사)
- 읽는 순서: 0절(지금 상태) → 6절(남은 일)에서 맡은 일 → 3절(노트 모양과 품질 기준) → 7절(작업 방법)

## 1. 무엇이고 왜

### 사용자 결정 (TODO.md D27 · D28)

- 영어가 프로그래밍보다 먼저예요. 그래서 허브에서 「처음 시작」 위에 「필수교양」 묶음을 두고, 그 안에 영어 단어장을 넣어요.
- 방식과 화면은 Anki 와 같게 해요. 복습 간격은 연구에 근거한 방식으로 정해요.
- 단어 구성은 아래 네 덱이에요. 기초 · 듣기 · 개발을 나란히 돌리고, 하루 새 카드는 기초에 가장 많이 나눠요.
- 뼈대와 코어는 먼저 만들고, 덱 채우기는 이 지시서로 이어서 해요.

### 사이트 방향과의 관계

- 교과서는 채점 · 반복으로 붙잡지 않는 게 원칙이에요(`specs/site-intent.md` 1절).

- 그래도 사이트가 채점하지는 않아요. 얼마나 잘 떠올랐는지는 사용자가 네 버튼으로 스스로 정해요.

## 3. 덱 데이터 모양

### 덱 (`vocab/decks/index.js`)

```js
VocabDecks.add({ id: 'base', name: '기초 일반 단어', desc: '…', tpl: ['r'], newPerDay: 10, sample: true });
```

| 칸 | 뜻 |
|---|---|
| `id` | 카드 id 의 첫 칸. **한 번 정하면 바꾸지 않아요**(바꾸면 그 덱의 복습 기록이 끊겨요) |
| `name` · `desc` | 화면에 보이는 이름과 한 줄 설명 |
| `tpl` | 이 덱의 노트가 만드는 카드 종류. `r` 읽기(영어 → 뜻) · `l` 듣기(소리 → 뜻) · `t` 쓰기(뜻 → 철자) |
| `newPerDay` | 하루에 꺼내는 새 카드 수의 기본값(1 ~ 100). 사용자가 설정에서 바꿀 수 있어요 |
| `credit` | 출처 표기. 덱 개요 화면 아래에 보여요(공개 목록을 쓴 덱은 꼭) |
| `sample` | 다 채우지 않았다는 표시. 화면에 「표본 n개」(50개까지) 또는 「채우는 중」 으로 보여요. 다 채우면 지워요 — 기초 덱은 차례표의 수와 같아졌을 때, 다른 덱은 노트가 50개를 넘으면 검사가 지우라고 해요 |

- 노트가 하나도 없는 덱은 화면에 「준비 중」 으로 나와요.

### 노트 (`vocab/decks/<덱>*.js`)

```js
VocabDecks.notes('base', [
  { id: 'allow', w: 'allow', rank: 435, ko: [['v', '허락하다, ~하게 해 주다']], ex: [['This ticket allows you to enter the museum.', '이 표가 있으면 박물관에 들어갈 수 있어요.']], forms: ['allows', 'allowed', 'allowing'], note: 'allow A to B: A가 B할 수 있게 해 주다' },
]);
```

| 칸 | 꼭? | 뜻 |
|---|---|---|
| `id` | ✅ | 노트 id. 영어 소문자 · 숫자 · 하이픈. 덱 안에서 겹치지 않아요. **내보낸 뒤에는 바꾸지 않아요** |
| `w` | ✅ | 카드에 보이는 단어(40자 안) |
| `ko` | ✅ | 뜻 목록 `[[품사, 뜻], …]` 1 ~ 3개 |
| `ex` | ✅ | 예문 목록 `[[영어, 한국어], …]` 1 ~ 2개 |
| `forms` | | 예문에 실제로 나온 다른 모양(복수 · 과거 등)만. 예문에서 굵게 보여 줘요 |
| `note` | | 쓰임 한 줄(자주 붙는 짝, 헷갈리는 점, 원래 뜻) |
| `say` | | 읽어 줄 글자가 `w` 와 다를 때(기호 · 줄임말). 예: `w: '( )'`, `say: 'parentheses'` |
| `pron` | | 소리 적기. 듣기 덱에서만 써요 |
| `tpl` | | 이 노트만 카드 종류를 달리할 때. 예: `['r', 't']` |
| `rank` | | 이 덱에서 배우는 차례(1부터). 쓰려면 덱의 모든 노트에, 오름차순으로. 기초 덱은 꼭 써요(차례표의 `no`) |

- 품사 코드: `n` 명사 · `v` 동사 · `adj` 형용사 · `adv` 부사 · `prep` 전치사 · `conj` 접속사 · `pron` 대명사 · `det` 한정사 · `art` 관사 · `aux` 조동사 · `num` 수사 · `int` 감탄사 · `phr` 표현 · `abbr` 줄임말 · `sym` 기호 · `affix` 접사
- 카드 id 는 「덱/노트/종류」 예요. 예: `base/allow/r`. 복습 기록의 열쇠라서 덱 id · 노트 id 를 바꾸면 기록이 끊겨요.
- 덱에서 노트를 지워도 그 카드의 기록은 지워지지 않고 남아요. 같은 id 로 다시 생기면 이어져요.
- 새 카드는 파일을 불러온 순서 · 파일 안에 적힌 순서대로 나와요. `rank` 는 그 순서가 맞는지 검사가 보는 데 써요.
- 표에 없는 칸을 쓰면 검사가 실패해요. 칸을 새로 만들려면 `tools/check_vocab.mjs` 의 `known` 과 이 표를 같이 고쳐요.

### 품질 기준

본보기는 둘이에요: 맨 처음 넣은 표본 10개(whether · example · provide · allow · include · result · available · instead · several · require)와 아래 「어려운 경우 본보기」.

뜻 (`ko`)
- 가장 흔한 뜻부터 1 ~ 3개만 적어요. 사전처럼 늘어놓지 않아요.
- 한 칸은 40자 안, 마침표 없이 써요.
- 품사마다 끝맺는 모양을 맞춰요.
  - 동사: 「~하다」 로. 예: 허락하다, 포함하다
  - 형용사: 꾸미는 모양으로. 예: 쓸 수 있는, 옳은
  - 명사: 명사로. 예: 결과, 오른쪽
  - 부사 · 전치사 · 접속사: 우리말에서 쓰는 모양 그대로. 예: 대신에, ~의, ~인지 (아닌지)
- 자리가 비는 곳은 `~` 로 적어요. 예: 「~하게 해 주다」
- 품사가 다른 중요한 뜻은 칸을 나눠요. 예: `like` 는 동사 「좋아하다」 와 전치사 「~처럼, ~같은」
- 덜 쓰이는 뜻은 빼거나 `note` 에 한 줄로 적어요. 예: `mine` 의 「광산」
- 품사가 같아도 뜻이 뚜렷이 다르면 칸을 나눠도 돼요. 예: `get` 은 「받다, 얻다」 와 「~해지다」
- 어느 뜻이 더 흔한지 애매하면 말에서 더 자주 듣는 쪽을 앞에 둬요. 그래도 모르겠으면 더 쉬운 뜻을 앞에 둬요. 두 뜻이 다 적혀 있으면 순서는 큰 문제가 아니에요.

예문 (`ex`)
- **직접 쓴 문장**이어야 해요. 사전 · 교재 · 다른 단어장에서 옮기지 않아요(저장소가 공개예요).
- 짧고 쉬운 문장으로 써요. 기초 덱은 검사가 두 가지를 봐요.
  - 14낱말까지
  - 차례표 밖 낱말은 예문마다 1개까지(사람 · 곳 이름처럼 문장 가운데의 대문자 낱말은 세지 않아요)
- 첫 예문에는 `w` 나 `forms` 의 한 모양이 들어 있어야 해요(검사가 봐요).
- 첫 예문은 `ko` 의 첫 뜻으로 쓴 문장이에요. 둘째 뜻을 보여 주려면 둘째 예문을 써요.
- 예문이 보여 주는 품사 · 뜻은 `ko` 에도 적어요. 예문에서 `others`(대명사)나 `Today is …`(명사)로 썼으면 `ko` 에 그 품사의 칸이 있어야 해요. 사전에 있는 뜻이 아니라 **예문과 `ko` 가 서로 맞는지**를 봐요.
- 한국어는 해요체로, 자연스러운 우리말로 써요. 낱말을 하나씩 옮긴 번역은 안 돼요.
- 한 파일 안에서 같은 문장 틀(I like … · This is …)만 되풀이하지 않아요. 같은 첫 두 낱말로 시작하는 예문이 한 파일에 12번을 넘지 않게 해요(기본 낱말이 몰린 `base-0001.js` 의 I have · This is 가 12번이에요).
- 이 덱은 어른인 사용자 본인의 학습 자료예요. 주제를 가려서 뜻을 빼거나 돌리지 않아요(LESSON.md U13).
  - 가장 흔한 뜻이 범죄 · 폭력 · 정치 · 종교 · 성 · 마약에 관한 것이어도 그 뜻을 첫 뜻으로 두고, 그 뜻을 그대로 쓰는 자연스러운 예문을 써요. 사전처럼 사실대로 써요(`The police arrested two men.` · `He was found guilty.`).
  - 다른 쓰임을 보여 주려고 억지 장면을 만들지 않아요(gun 을 물총으로, murder 를 추리 소설로 돌리지 않기). 낱말에 흔한 뜻이 여럿이면 흔한 순서대로 둬요.
  - 가장 흔한 뜻이 아니어도, 미국에서 알아들어야 하는 속어 뜻은 `note` 에 「(속어)」 로 적어요. 모르면 위험하거나 곤란해지는 뜻일수록 꼭 적어요: 마약(crack · pot · joint · high · dealer · stoned) · 술(shot · wasted) · 성(hook up · hit on · sleep with) · 범죄 · 폭력. 흔하게 쓰면 `ko` 칸으로 올려요.
  - 거친 말(`damn` · `bloody`)은 뜻 앞에 「(거친 말)」 을 붙여 말투만 알려요.
  - 쓰지 않는 것은 실제 사람 · 회사를 깎아내리는 문장뿐이에요(저장소가 공개라서).
- 기초 덱은 일상 문장, 개발 덱은 실제 에러 메시지나 문서에 나올 법한 문장으로 써요.
- 철자 · 낱말은 미국식이 기본이에요(color · neighbor · center · apartment). 영국에서 다르게 쓰면 `note` 에 「영국에서는 …」 으로 적어요.

다른 모양 (`forms`)
- **예문에 실제로 나온 모양만** 적어요(검사가 봐요). 예문에서 그 낱말을 굵게 보여 주는 데만 쓰여요. 예문에 `w` 그대로만 나오면 `forms` 를 쓰지 않아요.
- 예문에 안 나온 모양은 `note` 에 적어요: 불규칙하게 바뀌는 모양(`go - went - gone`), 짝이 되는 낱말(`he` 의 him · his).
- 차례표의 다른 모양 칸에 없는 모양이라도 예문에 나오면 적어요(예: `shoot` 의 `shot`).
- 차례표의 `forms` 칸에는 줄임말의 조각(`m` · `s` · `re` · `t` · `ll`)도 섞여 있어요. 그대로 다 옮기지 않아요.

쓰임 (`note`)
- `note` 에 쓴 규칙이 같은 카드의 예문과 어긋나지 않게 해요(예: 「동사 앞에 와요」 라고 쓰고 예문은 be 동사 뒤인 경우). 줄임 모양도 정확히: couldn't 는 could 를 줄인 꼴이 아니라 could not 을 줄인 꼴이에요.
- 한 줄만 적어요(90자 안). 자주 붙는 짝(`instead of A: A 대신`), 헷갈리는 점, 줄임 모양, 불규칙하게 바뀌는 모양(`know - knew - known`), 짝이 되는 낱말(`we` 의 us · our).
- 소리를 적을 때
  - 우리말 외래어 표기(「테크닉」 · 「칼럼」)를 소리로 적지 않아요. 영어 소리와 달라요.
  - 두 소리를 견주거나 소리 나지 않는 글자를 알릴 때만 한글로 비슷하게 대괄호에 적어요: `close` 동사 [클로즈] · 형용사 [클로스], `island` [아일런드].
  - 강세는 대문자로 적어요: 명사 RE-cord · 동사 re-CORD. 소리가 같은 다른 낱말이 있으면 그 낱말을 대괄호에: `read` 의 과거 [red].
  - 발음 기호(/…/)는 쓰지 않아요. 카드에서 소리를 들을 수 있어요.

### 어려운 경우 본보기

차례표 앞쪽은 관사 · 대명사 · 전치사 · 조동사라서 뜻을 쓰기가 가장 어려워요. 아래 14줄은 `check_vocab` 을 통과한 본보기예요. 그 차례의 파일을 쓸 때 **이 줄을 그대로** 넣어요.

- 덱에 이미 들어 있는 줄은 `check_vocab` 이 덱의 노트와 글자까지 대조해요(출력의 「덱에 든 N줄과 같음」). 아직 덱에 없는 줄은 그 차례의 파일을 쓸 때 그대로 넣어요.
- 덱에 든 노트와 이 본보기는 글자까지 같아야 해요(검사가 봐요). 한쪽을 고치면 다른 쪽도 같이 고쳐요.
- 대명사 · 전치사 · 접속사 · 물음말의 본보기가 더 필요하면 `base-0001.js` 를 봐요(it · that · there · what · if · at …).

- 관사(`the` · `a`): 품사는 `art`. 뜻 칸에 하는 일을 괄호로 적고, 우리말로 옮기지 않는다는 것은 `note` 에 적어요.
- 대명사 · 조동사 · 전치사: 가장 흔한 쓰임 하나를 뜻으로, 줄임 모양이나 자주 붙는 짝은 `note` 에 적어요.
- 뜻이 품사마다 다른 단어(`like` · `right`): 칸을 나누고, 예문도 뜻마다 하나씩(둘까지) 써요.
- 같은 글자가 다른 단어인 것(`mine` · `left` · `found` · `rose` · `wound`): 흔한 쪽을 첫 뜻으로, 다른 쪽은 둘째 칸이나 `note` 에 적어요.
  - 다른 쪽이 다른 동사의 과거 모양이면(`left` ← leave · `found` ← find · `rose` ← rise) `ko` 에는 차례표에 든 그 낱말 자신의 뜻만 두고, 과거 모양이라는 것은 `note` 에 적어요(본보기 `left`). 과거 모양은 leave · find · rise 의 카드에서 배워요.
- 숫자(`two` …)는 품사 `num`. 말에서만 쓰는 낱말(`yeah` · `okay`)은 어떤 말의 편한 모양인지 괄호로 적어요.
- 품사를 고르는 기준
  - 대답으로도 쓰는 부사(`sure` · `exactly` · `absolutely`)는 `adv` 로 하고 뜻 앞에 「(대답)」 을 붙여요. `int` 는 감탄으로 쓰는 뜻의 칸에 둬요(`yes` · `oh`, `well` 의 「음, 글쎄」, `welcome` 의 「어서 오세요」). 다른 품사로도 쓰는 낱말이라도 그 뜻이 감탄이면 `int` 칸이에요.
  - 구동사(`put on` · `drop off` · `fill out`)는 `v`. 동사가 아닌 묶음(`a lot` · `sort of` · `in detail` · `in fact`)은 `phr`.
  - 묶음을 뜻 칸에 적을 때는 표제어가 아니라 **묶음의 모양**으로 품사를 골라요.
    - 동사 + 전치사 · 부사(`depend on` · `go ahead` · `put away` · `look forward to`), 동사 + 목적어 틀(`regard A as B` · `remind A of B`)은 `v`.
    - be + 과거분사(`be based on` · `be supposed to` · `be stuck`)는 `phr`. be + 형용사는 표제어가 그 형용사면 `adj`(`able`: (be able to) ~할 수 있는).
    - 그 밖의 굳은 표현은 `phr`: 동사 + 명사 관용구(`make sense` · `kill time` · `give birth to`), 문장으로 굳은 말(`Excuse me.` · `I guess`), 동사가 없는 묶음(`according to` · `due to`).
  - 예문이 굳은 표현(`in detail` · `in common`)을 보여 주면 그 표현을 `phr` 칸으로 적거나, 낱말 자체의 뜻을 보여 주는 예문으로 바꿔요.
- 사용자가 이미 아는 단어는 「아는 단어 한꺼번에 넘기기」 화면(5절)에서 넘겨요. 그래도 덱에는 다 넣어요.

## 4. 간격 계산 규칙

코어를 고칠 때만 읽어요.

### 지금 규칙 (모두 Anki 기본값과 같은 방향)

| 무엇 | 값 | 어디 |
|---|---|---|
| 알고리즘 | FSRS-6, 기본 매개변수 21개 | `vocab/fsrs.js` |
| 목표 기억률 | 90% | `VocabCore.engine` |
| 새 카드 학습 단계 | 1분 → 10분 | 〃 |
| 틀린 카드 다시 학습 단계 | 10분 | 〃 |
| 간격 흩뜨리기 | 켬(2.5일 이상인 간격만) | 〃 |

| 하루 새 카드 | 덱마다(기본값은 덱의 `newPerDay`) | `cfg.newPerDay` |

네 버튼
- 다시(1): 못 떠올림. 첫 단계로 돌아가요. 복습 카드였으면 「다시 학습」 이 되고 틀린 횟수가 올라요.
- 어려움(2): 첫 단계에서는 첫 두 단계의 평균(6분), 그 뒤 단계에서는 그 단계를 되풀이해요.
- 알맞음(3): 다음 단계로. 단계가 끝나면 복습 카드로 졸업해요.
- 쉬움(4): 바로 복습 카드로 졸업해요.

오늘 볼 카드를 고르는 순서(`VocabCore.pick`)
1. 지금 다시 볼 때가 된 학습 카드
2. 복습 카드와 새 카드를 고르게 섞기(남은 수의 비율대로)
3. 둘 다 없으면 20분 안에 돌아올 학습 카드
4. 그것도 없으면 끝

- 같은 노트의 다른 카드(읽기와 듣기)는 같은 날 겹쳐 내지 않아요.
- 복습 카드는 밀린 날이 오래된 것부터, 같은 날끼리는 날마다 다르게 섞어요.

### 간격 계산기의 출처와 다른 점

- `vocab/fsrs.js` 는 공개 구현 ts-fsrs 5.4.2(MIT)의 소스를 읽고 같은 계산을 옮긴 것이에요. 라이브러리 파일을 그대로 넣지 않았어요.
- 일부러 다르게 한 곳은 셋이에요(파일 머리 주석에도 있어요).
  1. 「어려움」 을 둘째 단계부터 누르면 그 단계를 되풀이해요(Anki 방식). 참조 구현은 늘 6분이에요.
  2. 지난 날 수를 UTC 날짜가 아니라 「새벽 4시에 바뀌는 하루」 로 세요.
  3. 흩뜨리기 씨앗은 「복습 시각(초)_복습 횟수」 예요. 기기가 달라도 같은 값이 나와요.
- 참조 구현과 숫자가 같은지는 6절 W0 로 확인해요.

### 바꿀 때 조심할 것

- **상태는 기록을 처음부터 다시 계산한 값**이에요(5절). 그래서 계산 규칙(매개변수 · 목표 기억률 · 학습 단계 · 하루 경계)을 바꾸면 모든 카드의 지난 기록이 새 규칙으로 다시 계산되고, 다음 복습 날이 한꺼번에 움직여요.
- 규칙을 바꾸려면 `VocabCore.sig` 도 같이 바꿔요. 그래야 기기마다 상태 캐시를 버리고 다시 계산해요.
- 목표 기억률을 사용자가 바꾸게 하려면, 바꾼 날 복습이 몰리지 않게 할 방법을 먼저 정해요. 지금은 화면에 그 설정이 없어요.

## 5. 저장 · 기기 연동

### 조각 둘

| localStorage 열쇠 | 내용 | 기기 연동 · 백업 |
|---|---|---|
| `academy.vocab` | `{ v, mt, resetAt, cfg, log }` | 들어가요 |
| `academy.vocab.cache` | `{ v, sig, recs, extra, sum, stale }` | 안 들어가요(다시 만들 수 있어요) |

- `log`: 카드 id → 사건 문자열
- `mt`: 마지막으로 바뀐 시각(밀리초). 기기 연동이 「올릴 것이 있나」 를 볼 때 써요
- `resetAt`: 기록을 초기화한 시각. 그 전 사건은 합칠 때 버려요
- `cfg`: `{ t 바꾼 시각, tz 시간대(분), roll 하루가 바뀌는 시, newPerDay, maxRev, auto 소리 자동 재생 }`
- `recs`: 카드 id → 상태(기록에서 계산한 값)
- `sum`: 허브 카드가 읽는 요약. 복습 카드의 「하루 번호 → 장 수」 표가 들어 있어서 허브는 날이 바뀌어도 오늘 몫을 셀 수 있어요
- `stale`: 다른 페이지에서 기기 연동이 기록을 받아 합쳤다는 표시. 단어장을 열면 다시 계산하고 지워요

### 사건 문자열

- 사건 하나 = 시각 6글자(36진수, 2026-01-01 UTC 부터 흐른 초) + 종류 1글자 = 7글자
- 종류: `1` 다시 · `2` 어려움 · `3` 알맞음 · `4` 쉬움 · `0` 되돌림(무효) · `s` 아는 단어로 넘김 · `u` 넘김 풀기 · `f` 처음부터 다시 · `p` 넘기기 화면에서 보고 지나감
- 상태 계산(`VocabCore.replay`)은 모르는 종류를 건너뛰어요. `p` 처럼 간격과 상관없는 표시는 그래서 옛 버전이 읽어도 탈이 없어요.
- 한 카드 안에서 시각은 늘 앞 사건보다 뒤예요(시계가 어긋난 기기에서도 순서가 지켜져요).
- 되돌리기는 사건을 지우지 않고 종류를 `0` 으로 바꿔요.

### 합치기

- 두 기기의 기록은 사건의 **합집합**이에요(`Sync.mergeVocab`).
  - 같은 시각의 사건이 양쪽에 있으면 `0`(되돌림)이 이겨요.
  - 초기화 시각보다 앞선 사건은 버려요.
  - 설정은 최근에 바꾼 쪽을 따라요.
- 합치는 차례 · 횟수와 무관하게 같은 결과가 나와요. 그래서 복습 기록이 사라지거나 두 번 세어지지 않아요.
- 단어장은 프로필과 따로 도장(`mt`)을 봐요. 복습만 한 기기의 화면 설정이 「더 최근」 으로 잘못 이기지 않게 하려는 거예요.
- 단어장 페이지는 카드마다 올리지 않아요. 30초 쉬거나 화면을 떠날 때 한 번 올려요.

### 아는 단어 한꺼번에 넘기기 (v2.46.1)

- 왜: 기초 덱의 앞쪽은 be · the · you 같은 낱말이에요. 아는 단어가 새 카드로 나오지 않게 먼저 걸러 내요.
- 화면(`VocabApp.viewKnown`, 주소 `#known/<덱>`): 덱 개요의 「아는 단어 한꺼번에 넘기기」 로 들어가요.
  - 아직 안 본 단어를 덱 순서대로 20개씩 보여 줘요. 뜻은 보여 주지 않아요(뜻을 보고 「안다」 고 누르지 않게).
  - 아는 단어만 눌러 표시하고 「표시한 n개 넘기고 다음」 을 눌러요. 「이 화면 전부 알아요」 도 있어요.
  - 아는 단어가 절반이 안 되는 화면이 두 번 이어지면 「카드로 배우는 게 좋아요」 라고 알려요.
  - 「앞 화면으로」 는 그 화면에서 남긴 기록을 무효로 돌리고, 골랐던 그대로 다시 보여 줘요.
- 기록(`VocabCore.sweep`): 한 화면을 한 묶음으로 남겨요. 표시한 단어의 카드에는 `s`, 나머지 카드에는 `p`(보고 지나감).
  - `p` 는 간격 계산과 상관없어요. 그 카드는 그대로 새 카드로 나와요. 넘기기 화면만 읽어요.
  - `p` 가 있거나 넘겼다가 푼(`u`) 단어는 다음에 들어왔을 때 빼고 보여 줘요(`VocabCore.unseenNotes` 의 `passed`).
  - 그래서 덱에 단어가 더 들어온 뒤 다시 와도, 전에 지나간 단어를 또 넘기지 않고 새로 들어온 단어부터 이어져요.
  - 지나간 단어를 다시 보려면 화면의 「지나간 단어 n개도 다시 보기」.
- 읽기 카드(`r`)가 있는 노트만 올려요. 듣기 카드만 있는 노트는 글자를 보고 고를 수 없어서 빼요(듣기 덱에는 버튼이 없어요).
- 넘긴 단어를 한 장씩 되돌리는 길: 찾아보기의 「아는 단어」 → 카드 정보 → 「다시 배우기」.
- 고르던 것은 「넘기고 다음」 을 누를 때 저장돼요. 그 전에 화면을 떠나면 그 화면에서 고르던 것은 버려요.

### W2. 듣기 덱 (`listen`)

강의에서 귀로 들리는 말이에요. 갈래 넷, 노트 약 310개(실제 수는 0절 표).

1. **기호와 코드 읽는 법** (약 80): 기호의 영어 이름(`( )` parentheses · `#` hash · `==` double equals), 던더(`__init__` 은 dunder init), 이름 짓는 법(snake case · camel case), 소리 내어 읽는 코드 · 줄임말(`elif` · `str` · `SQL` sequel · `JSON` Jason · `sudo`)
2. **강의 말버릇** (약 100): go ahead and · in this case · it turns out · let's say · hit enter · figure out · so to speak · under the hood
3. **외래어와 소리가 다른 단어** (약 80): 우리말 외래어로 아는데 영어 소리가 뚜렷이 다른 낱말(data · variable · parameter · module · image · label · queue · width · height)
4. **숫자와 식 읽는 법** (약 50): 3.14 three point one four · x² x squared · 10 ÷ 2 ten divided by two · O(n) big O of n · 404 four oh four

고른 근거 (2026-11-12 에 셈)
- 기호 · 코드 이름: 교과서 21개의 코드에 나오는 횟수. `"` 33,335 · `(` 27,786 · `==` 1,312 · `__init__` 235 · `elif` 189
- 외래어
  - 이 사이트에 나오는지는 교과서 우리말 글의 횟수로 봤어요. 데이터 262 · 메서드 207 · 모듈 114 · 튜플 99
  - 배우는 차례는 강의 자막에서 영어로 들리는 횟수로 매겨요. variable 890 · parameter 85
  - 교과서는 변수 · 정수처럼 우리말로 적은 곳이 많아서, 외래어 횟수만 보면 강의에서 자주 듣는 말이 뒤로 밀려요.
- 말버릇 · 기호를 부르는 말 · 숫자 읽기: CS50 강의 자막 24개에서 센 횟수예요(파이썬 10 · AI 7 · SQL 7, 강사 셋, 약 44만 낱말). 한 강사만 쓰는 말보다 여럿이 쓰는 말을 앞에 둬요. go ahead and 951 · in this case 396 · it turns out 294
  - 자막은 횟수만 세고 저장소에 넣지 않아요. CS50 자료는 CC BY-NC-SA 예요. 예문도 자막 문장을 옮기지 않고 직접 써요.
- 빼는 것
  - 기초 덱에 이미 있는 한 낱말(actually · basically · indeed)
  - 속어 덱에 있는 말(gonna · wanna · gotta)
  - 기초 덱이 이미 다루는 문법 묶음(instead of · rather than · according to)
- 개발 덱(W3)과 나누기: 강의 말투의 형용사(naive · arbitrary · elegant)는 개발 덱으로 보내요. edge case · boilerplate · trade-off · under the hood 는 이 덱에 둬요. `str` · `len` 처럼 두 덱에 다 나오는 줄임말은, 이 덱은 읽는 소리를, 개발 덱은 풀어 쓴 뜻을 가르쳐요.

차례와 파일
- 갈래마다 빈도 순으로 줄 세운 뒤, 갈래 크기의 비율대로 섞어요. 첫 100장에 네 갈래가 다 나오게 하려는 거예요.
- 합치는 사람이 섞어서 `listen-001.js` · `listen-101.js` · `listen-201.js` · `listen-301.js` 로 나눠요. 파일 이름의 숫자는 그 파일 첫 노트의 차례예요. `rank` 는 쓰지 않아요.

노트 모양
- 기호 · 식 · 코드 · 줄임말(`w` 가 영어 낱말이 아닌 것)
  - `w` 에 글자 그대로, `say` 에 강의에서 읽는 말을 적어요(`w: '( )'`, `say: 'parentheses'`).
  - `tpl: ['r', 'l']` 이에요. 보고 읽는 법을 떠올리는 카드와 듣고 뜻을 떠올리는 카드가 같이 생겨요.
  - 읽는 말을 예문에 넣고 `forms` 에 적어요. 그래야 뒷면 예문에서 굵게 보여요.
  - `say` 는 기기의 읽어 주는 소리가 바르게 읽도록 써요. 소리가 철자와 다른 줄임말은 실제 낱말로 소리를 맞춰요(`JSON` → `Jason`, `sudo` → `sue dough`).
- 낱말 · 묶음(외래어 · 말버릇): `w` 에 그대로 적고, 카드는 덱 기본(듣기)만이에요.
- `pron` 은 모든 노트에 적어요. 모양은 「강세 표시 철자 [한글 소리]」, 60자 안이에요.
  - 철자를 사전식 음절로 나누고 강세 음절만 대문자로 적어요: `pa-RAM-e-ter [퍼래미러]`. 한 음절 낱말은 통째로 대문자예요: `QUEUE [큐]`.
  - 묶음은 낱말 사이를 빈칸으로 두고, 가장 센 음절만 대문자로 적어요: `go a-HEAD and [고어헤든]`.
  - 한글은 미국 영어를 보통 빠르기로 말할 때 들리는 소리예요. 외래어 표기법(「파라미터」)으로 적지 않아요.
    - 약한 모음은 [어]예요. 모음 사이의 t · d 는 [ㄹ]로 적어요(data [데이러]).
    - 이어 나는 소리는 붙여 적어요(go ahead and [고어헤든]).
    - th 는 [ㅆ] · [ㄷ], f · v · z 는 [ㅍ] · [ㅂ] · [ㅈ] 로 적어요. r 과 l 처럼 한글로 못 가르는 차이가 뜻을 가르면 `note` 에 적어요.
  - 기호 · 식은 `say` 의 소리를 적어요.
- `note`(90자 안)에 적는 것
  - 우리말 외래어와 다른 점(「모델」 과 달리 [마들])
  - 다른 이름(`#` 은 pound sign · hashtag 라고도 해요)
  - 빨리 말할 때 들리는 모양
  - 헷갈리는 짝(parenthesis 는 하나, parentheses 는 둘)
- 예문
  - 강의에서 강사가 할 법한 말로 써요.
  - 기호는 예문에 넣지 않고 말로 써요. 읽어 주는 소리가 예문도 읽기 때문이에요: `Put the arguments inside the parentheses.`
  - 16낱말까지예요(검사가 봐요).
  - 갈래 파일마다 같은 첫 두 낱말로 시작하는 예문은 6번까지예요. 그래야 섞어 합친 파일에서 12번을 넘지 않아요.
- 품사: 기호 `sym` · 코드 이름 `n` · 줄임말 `abbr` · 읽는 식 `phr` · 수 `num`. 말버릇은 3절 「품사를 고르는 기준」 그대로예요(구동사 `v`, 굳은 표현 `phr`).
- 검사(`check_vocab` ⑥)
  - 듣기 덱 노트에 `pron` 이 있고 모양(대문자 강세 · 끝의 [한글])이 맞는지 봐요.
  - `say` 가 있는 노트의 카드가 읽기 · 듣기 둘인지 봐요.
  - 낱말이 아닌 `w` 에 `say` 가 있는지 봐요.
  - 예문이 16낱말을 넘지 않는지 봐요.
- 사람이 볼 것: 읽어 주는 소리가 기기마다 달라요. 사용자 PC 와 폰에서 몇 장을 들어 봐야 해요(TODO 1-4).

### W3. 개발 단어 덱 (`dev`)

- 갈래 다섯
  1. 용어의 영어 이름: 변수 = variable. 재료는 `shared/glossary.js`(94항목 중 영어가 같이 적힌 것은 36개)
  2. 원래 뜻과 개발 뜻이 다른 단어: argument · string · raise · yield · branch · commit. `note` 에 「원래 뜻: …」 을 적어요
  3. 에러 메시지와 공식 문서 단어: invalid · unexpected · missing · required · denied · exceeded · deprecated. 재료는 `shared/errors.js` 와 파이썬이 실제로 내는 에러 글
  4. 줄임말 풀이: `str` = string · `len` = length · `mkdir` = make directory. `note` 에 풀어 쓴 말을 적어요
  5. 접두사와 접미사: un- · re- · sub- · -able. 예로 `iterable` · `callable` · `unsupported`
- 단어는 감으로 고르지 않고 데이터에서 뽑아요.
  - 교과서 21개의 `content.js` · `book.js` 에 실제로 나오는 영어 낱말을 스크립트로 세요.
  - 파이썬 키워드와 내장 이름은 `keyword.kwlist` · `dir(builtins)` 로 뽑아요.
- 차례: 파이썬 교과서 진도 순서(그 낱말이 처음 나오는 레슨 순서)로 매겨요.
- 카드 종류: 덱 기본은 `r`. 코드에 직접 치는 이름(`length` · `append` 같은 것)은 `tpl: ['r', 't']` 로 철자 카드도 만들어요.
- 기초 덱과 같은 단어가 나와도 돼요. 개발 덱에는 개발 뜻을 적어요.

### W10. 속어 · 거친 말 덱 (`slang`) — ✅ 끝남 (v2.46.5, 296개)

- 사용자가 정했어요(TODO.md D29): 미국에서 들으면 알아들어야 하는 말을 따로 모은 덱이에요. 모르면 위험하거나 곤란해지는 말을 먼저 둬요.
- 갈래 일곱: ① 모욕 · 비하어(아시아인 · 한국인을 겨냥한 말 포함) ② 욕 · 거친 말 ③ 성 ④ 마약 ⑤ 술 ⑥ 범죄 · 사기 · 위험한 상황 ⑦ 일상 속어(친구끼리 쓰는 말)
- 기초 덱(NGSL)에 있는 낱말이라도 속어 뜻이 따로 있으면 이 덱에 그 뜻으로 넣어요. 카드 id 는 덱이 달라서 겹치지 않아요.
- 카드 종류는 읽기와 듣기(`tpl: ['r', 'l']`)예요. 귀로 듣고 알아채는 게 목적이라, 소리가 비슷해 헷갈리는 짝(slut ↔ slot · crack ↔ cracker)은 `note` 에 적어요.
- 뜻 앞에 말의 세기를 붙여요: 「(속어)」 · 「(거친 말)」 · 「(모욕)」 · 「(아주 심한 모욕 — 쓰지 마세요)」 · 「(편한 말)」(누구나 쓰는 편한 말). 경찰 명령 · 정식 이름처럼 속어가 아닌 말은 표시 없이 써요. 사람을 깎는 뜻은 (모욕), 뜻마다 세기가 다르면 뜻마다 붙여요.
- note 의 「원래 뜻」 · 「~에서 온 말」 은 속뜻이 정말 그 겉뜻에서 나왔을 때만 써요. 뿌리가 다르거나 확실하지 않으면 「~도 같은 글자」 로 적어요(검수에서 bust · bail · chug · horny 가 걸렸어요).
- 예문은 그 말을 실제로 듣게 되는 장면 그대로 써요(권하는 말 · 욕하는 말 · 작업 거는 말). 번역도 말투를 살려요.
- 순서는 「들을 가능성 × 모르면 생기는 위험」 이 큰 것부터예요(파일에 적힌 순서가 배우는 순서).
- 형식 · 품질 기준은 3절 그대로예요. 예문 낱말 수 · 차례표 밖 낱말 검사는 기초 덱에만 걸려요.

### 덱 파일 쓰기

- 덱 파일은 새로 쓰는 파일이라 통째로 써도 돼요.
- 있는 파일의 노트를 고칠 때는 python 스크립트로 「바꿀 글자가 정확히 한 번 있는지」 확인하고 바꿔요(LESSON.md R7).
- 노트 한 줄에 노트 하나. 줄 순서가 카드가 나오는 순서예요.

### 검수 (두 번째 읽기)

검사 도구는 모양만 봐요. 뜻이 맞는지는 읽어 봐야 알아요. 이 덱은 영어가 약한 사용자가 그대로 믿고 외우는 것이라, 틀린 뜻 하나가 그대로 외워져요.

- 파일을 쓴 뒤, **쓴 쪽과 다른 눈**으로 그 파일의 노트를 전부 읽어요. 새 에이전트에게 파일과 아래 물음만 줘요(쓴 과정은 주지 않아요).
- 노트마다 볼 것
  1. 첫 뜻이 그 단어의 가장 흔한 뜻인가
  2. 품사 코드가 그 뜻과 맞나
  3. 첫 예문이 첫 뜻으로 그 단어를 쓰고 있나
  4. 한국어가 예문의 뜻과 같은가, 우리말로 자연스러운가
  5. 영어 예문이 문법에 맞고 자연스러운가
  6. `note` 가 사실인가(짝 · 줄임 모양)
  7. 둘째 예문이 쓴 품사 · 뜻이 `ko` 에 적혀 있나(예문에서 대명사로 쓴 낱말이 `ko` 에 없으면 안 돼요)
  8. `note` 의 규칙이 그 카드의 예문과 어긋나지 않나
- 결과는 「고칠 줄: 차례 · 단어 · 무엇을 · 왜」 목록으로 받아요. 받은 것을 그대로 믿지 말고 하나씩 보고 고쳐요(LESSON.md R9).
- PR 설명에 파일마다 「노트 수 · 검수에서 고친 수」 를 적어요.

### 나눠 맡기 (여러 에이전트)

- **한 파일은 한 작업자만** 써요. 이웃한 줄을 여럿이 채우면 합칠 때 충돌해요(LESSON.md R16).
- 맡길 때 브리프 맨 앞에 적을 것
  - 시작해야 하는 커밋(HEAD). 따로 뗀 작업 폴더(worktree)는 옛 main 에서 만들어질 수 있어요. 첫 명령으로 `git reset --hard <커밋>` 과 `git log --oneline -1` 확인을 시키고, 다르면 멈추게 해요(LESSON.md R16)
  - 맡은 파일 이름과 차례 범위
  - 3절의 노트 모양과 품질 기준, 본보기 파일
  - 끝 검사: `node tools/check_vocab.mjs`. 다른 파일과 글자까지 같은 예문도 잡아요. 다만 동시에 쓰는 다른 작업자의 파일은 아직 없으니, 합치는 사람이 합친 뒤 한 번 더 돌려요
  - 임시 파일(노트 데이터 · 스크립트)은 scratchpad 안의 맡은 파일 이름 하위 폴더(`w0801/` 처럼)에만. 여럿이 같은 폴더를 쓰면 같은 이름의 파일을 서로 덮어써요
- `vocab/index.html` · `vocab/decks/index.js` · 이 문서의 표는 나눠 맡기지 않고 합치는 사람이 고쳐요.
  - 작업자는 자기 작업 폴더에서 검사를 통과시키려고 `index.html` 의 한 줄 · 0절 표와 HANDOFF · TODO 0절 「영어 단어장」 줄의 숫자를 고쳐도 돼요. 합치는 사람은 덱 파일만 가져와요.
- 합친 뒤에는 파일마다 위 「검수」 를 하고, 합치는 사람도 파일마다 30개쯤을 직접 읽어 봐요(LESSON.md R9).
  - 검수 지적을 쓴 쪽에 돌려보내 고치게 했으면, 고치기 전 파일을 남겨 두고 바뀐 노트만 전후로 대조해 읽어요(지적과 다르게 고친 곳 · 덤으로 고친 곳을 확인). 도구: `node tools/vocab_diff.mjs <전 파일> <후 파일>` — rank 가 없는 덱은 id 로 짝지어요.

- Anki 설명서: FSRS 는 Anki 23.10 부터 쓸 수 있고 목표 기억률 기본값은 90%예요. 학습 단계의 예는 1분 · 10분이고, 「어려움」 은 첫 단계에서 6분(첫 두 단계의 평균), 그 뒤 단계에서는 그 단계를 되풀이해요. 다른 카드가 없으면 20분 안에 돌아올 학습 카드를 미리 보여 주고, 하루는 새벽 4시에 바뀌어요: [덱 옵션](https://docs.ankiweb.net/manual/deck-options) · [환경 설정](https://docs.ankiweb.net/manual/preferences)
- Anki 설명서의 주의: 못 떠올렸는데 「다시」 대신 「어려움」 을 누르면 FSRS 가 맞힌 것으로 보고 간격을 너무 길게 잡아요. 그래서 덱 목록의 안내 글에 「못 떠올렸으면 다시」 를 적어 두었어요.

알려진 한계
- 허브 카드의 수는 단어장 페이지가 마지막으로 계산한 요약에서 나와요. 다른 페이지에서 기기 연동이 기록을 받은 직후에는 「열면 다시 계산해요」 라고만 보여요.
- 카드를 누를 때마다 기록 전체를 저장해요. 카드가 수천 장이 되어 느려지면 저장을 묶는 방법을 찾아요.
- 시간대는 처음 연 기기의 것을 써요. 다른 시간대로 가도 하루가 바뀌는 때는 그대로예요.
- 읽어 주는 소리는 브라우저 기능이라 기기마다 목소리가 달라요. 소리가 안 나는 브라우저에서는 듣기 카드가 글자로 나와요.
- 「전체 초기화」(사이트 설정)는 단어장 기록을 지우지 않아요. 단어장 기록은 단어장 설정에서 따로 지워요.
