## 1. 한 줄로

**「프로그램 여러 개가 CPU 하나·메모리 하나·디스크 하나를 어떻게 나눠 쓰나」 를 내 우분투 VM 에서 직접 일으켜 보며 배우기.** 프로세스를 만들고(fork·exec), 일부러 경쟁 상태를 일으켜 락으로 고치고, 내 프로그램의 주소 공간과 시스템 콜을 들여다봐요. 끝에는 **파이썬으로 작은 셸**을 만들어요.

## 2. 다른 교과서와의 경계 (겹침 정리 — 꼭 지킬 것)

| 주제 | 이미 있는 교과서 | **운영체제 교과서 (새로)** | 예정 |
| --- | --- | --- | --- |
| VM·우분투 설치·apt·sudo·권한(`chmod`)·`ps`·`top`·`kill`·`free`·`df` | ✅ 리눅스 U0~U14 — **쓰는 법** | 다시 가르치지 않음. 「먼저 꼭: 리눅스 UB1(연습장 완성)」 + 「필요한 명령」 은 리눅스 레슨으로 링크. 여기서는 **왜 그렇게 도는지(원리)** | — |
| 명령 줄·파이프·리다이렉트(`\|` · `>`) | ✅ 터미널 T0~T5 — 쓰는 법 | 파이프·리다이렉트가 **안에서 어떻게 만들어지나**(`os.pipe` · `dup2`)만 | — |
| 큐·힙·정렬 | ✅ 알고리즘 교과서 | 스케줄러 대기 줄로 **다시 쓰기만**(링크) | — |
| 파이썬 문법(`def` · `class` · `with` · 예외) | ✅ 파이썬 교과서 | 다시 가르치지 않음 — `import os` · `threading` · `signal` 같은 **운영체제 쪽 모듈만** 새로 | — |
| 「운영체제가 하는 일」 한눈에 · 프로그램 vs 프로세스 | — | ✅ **K0 이 기준**(자세히) | T1 CS 의 운영체제 맛보기 1~2레슨은 **K0 을 한 쪽으로 줄인 것 + 「더 알아보기 → 운영체제 K0」** 링크(겹치지 않게 — CS 쪽은 그림 한 장 수준) |
| 시스템 콜을 어셈블리로 직접 부르기(`syscall` 명령) · 레지스터 | — | 시스템 콜이 **무엇이고 언제 일어나는지**(strace 로 보기)까지 | ✅ T10 어셈블리어가 「`rax` 에 번호 넣고 `syscall`」 |
| CPU·캐시·메모리 계층 하드웨어 | — | 「페이지·TLB 가 있다」 정도 | ✅ T1 CS |

- 원칙: 리눅스 교과서는 **「관리하며 쓰기」**, 운영체제 교과서는 **「안에서 무슨 일이 일어나나 — 직접 일으켜 보기」**.

## 3. 연습 방법 (교과서 원칙 그대로)

- 연습은 **사용자의 진짜 도구**: 리눅스 교과서에서 만든 **VirtualBox 의 우분투 26.04 VM**(스냅샷 「연습장 완성」) + **VS Code → Remote - SSH**(리눅스 U13 — Windows 의 VS Code 로 VM 안 파일을 고치고 VM 의 터미널에서 실행). 사이트 안 가짜 운영체제는 만들지 않아요.
- 코드는 **파이썬 중심**(9절 Q1): 우분투에 처음부터 들어 있는 `python3` 의 `os`(`fork`·`exec*`·`wait`·`pipe`·`dup2`) · `signal` · `threading` · `queue` · `mmap`. 「파이썬이 숨기는 것」 이 있는 곳만 **C 맛보기**(K14 의 `hello.c` 를 `gcc` 로 — `build-essential` 은 리눅스 U7 에서 이미 설치).
- 관찰 도구: `ps -o pid,ppid,stat,ni,cmd` · `/proc/<pid>/`(status · maps · fd) · `strace`(없으면 `sudo apt install strace`) · `/usr/bin/time -v`(없으면 `sudo apt install time`) · `ls -i` · `stat` · `ln`.
- **눈으로 보기 어려운 것만 브라우저 그림**(보조 — 알고리즘 교과서의 👀 처럼, 누를 때만): CPU 스케줄링 **간트 차트**(FCFS · SJF · 라운드 로빈, 슬라이더로 타임 슬라이스) · **페이지 교체 표**(FIFO · LRU, 프레임 수 슬라이더 · 페이지 폴트 칸 색칠) · **교착 상태 그림**(두 스레드 · 두 락 화살표). 수학 교과서의 `core/figure.js` 방식(JS 만으로 즉시 다시 그림 · 파이썬 엔진 없음)으로 새 그림 종류 3개.
- 실험이 VM 을 무겁게 만들 수 있는 쪽(프로세스 폭탄 방지 · 메모리 많이 쓰기)은 **「먼저 꼭: 스냅샷」** + 코드에 상한(예: `for _ in range(5)`)을 둬요.

## 5. 목차 (챕터 4 · 레슨 17 + 만들어 보기 4)

레슨 id 는 `K0`~`K16`(Kernel — `O` 는 숫자 0 과 헷갈려서), 챕터 끝 만들어 보기 `KB1`~`KB4`. 쪽 수는 2~4쪽(설명 + 예제), 마지막 쪽은 「🛠 만들어 보기」.

### 챕터 1 · 프로세스: 프로그램이 살아 움직이는 단위

| id | 제목 | 쪽(주요 내용) | 만들어 보기 |
| --- | --- | --- | --- |
| K0 | 운영체제가 하는 일 | ① 운영체제 = 프로그램들과 하드웨어 사이의 관리자(그림: 앱들 → 커널 → CPU·메모리·디스크) · ② 프로그램(디스크의 파일) vs 프로세스(실행 중인 것 — 같은 프로그램 여러 개) · ③ 커널 모드 / 사용자 모드 맛보기(K14 예고) | 같은 `python3` 를 터미널 두 개에서 띄우고 PID 가 다른지 `ps` 로 ☐ |
| K1 | `/proc` 으로 프로세스 들여다보기 | ① `ps -o pid,ppid,stat,cmd` · 부모·자식(PPID) · `pstree` · ② `/proc/<pid>/status`(State · VmRSS · Threads) · `/proc/self` · ③ 상태 글자 R·S·D·Z·T | 내 파이썬이 `os.getpid()` · `os.getppid()` 를 찍고, `/proc/<pid>/status` 의 `PPid:` 와 같은지(파이썬 검사) |
| K2 | `fork`: 나를 둘로 | ① `os.fork()` 는 한 번 불러 **두 번 돌아옴**(부모는 자식 PID, 자식은 0) · ② 자식은 부모의 복사본(변수를 바꿔도 부모는 그대로 — 주소 공간 분리, K10 예고) · ③ `os.waitpid` · 종료 코드 · 좀비(Z)와 고아 | 자식 3개를 만들어 각자 다른 숫자를 계산하고, 부모가 기다려 종료 코드를 모으기(파이썬 검사) |
| K3 | `exec`: 다른 프로그램으로 바꿔 타기 | ① `os.execvp("ls", ["ls", "-l"])` — 지금 프로세스가 **다른 프로그램이 됨**(PID 그대로) · ② `fork` + `exec` + `wait` = 셸이 명령을 실행하는 방법 · ③ `subprocess.run` 은 이걸 대신 해 주는 것 | `fork`·`execvp`·`waitpid` 로 `date` 를 실행하고 「종료 코드 0」 출력(파이썬 검사) |
| K4 | 시그널: 프로세스에게 보내는 쪽지 | ① `kill -l` · SIGINT(Ctrl+C) · SIGTERM · SIGKILL(못 막음) · SIGSTOP/SIGCONT(Ctrl+Z · `fg`) · ② `signal.signal(signal.SIGINT, 처리 함수)` — Ctrl+C 를 눌러도 「저장하고 끝낼게요」 · ③ 리눅스 U10 의 `kill` 은 이것 | Ctrl+C 를 받으면 「정리 중…」 을 찍고 끝나는 프로그램(`os.kill(os.getpid(), signal.SIGINT)` 로 스스로 보내 확인 — 파이썬 검사) |
| K5 | 파이프와 리다이렉트는 어떻게 만들어지나 | ① 파일 디스크립터 0·1·2(stdin·stdout·stderr — K15 에서 자세히) · ② `os.pipe()` → 읽는 끝 · 쓰는 끝 · `os.dup2` 로 1번을 바꿔 끼우기 · ③ `ls \| wc -l` 을 손으로 만들기 | `fork` 두 번 + `pipe` + `dup2` 로 `echo 하나 둘 셋 \| wc -w` 만들기 → `3`(파이썬 검사) |
| **KB1** | 🛠 만들어 보기: 내 미니 셸 1단계 | `mysh$ ` 프롬프트 → 한 줄 읽기 → `fork`·`execvp`·`waitpid` → 종료 코드 표시 · `cd` 와 `exit` 는 **셸 안에서**(왜 `cd` 는 따로인가: 자식의 폴더만 바뀌니까) · Ctrl+C 는 셸이 아니라 실행 중인 명령만 멈추게 | 입력 몇 줄을 넣어 출력 비교(파이썬 검사 — `printf 'echo hi\ncd /tmp\npwd\nexit\n' \| python3 mysh.py`) + ☐ |

## 6. 「만들어 보기」 모양과 검사

- 모양은 다른 교과서와 같음: 문장 문제 · **필요한 문법/명령**(실제 코드 — `os.fork()` · `os.execvp(cmd, args)` · `with lock:` · `strace -c`) · 입력 예/출력 예 · 예시 답 · (화면에서만 보이는 것은) 확인할 것 ☐.
- **자동 검사**: 파이썬 문제는 지금 `check_book` 처럼 **python3 로 진짜 실행**(CI 는 ubuntu-latest — `os.fork`·`/proc` 이 있음). 시간·메모리처럼 기계마다 다른 값은 출력 예를 **범위로**(예: `걸린 시간 1.0초 근처` → 검사는 `0.9~1.6`). 이를 위해 `check_book` 에 출력 비교 방식 `checkMode: 'range'`(숫자 칸만 허용 범위)를 더함.
- **자동 검사가 안 되는 것** — `strace`·`vmstat`·`/usr/bin/time -v`·OOM·여러 터미널: `noRun` + **확인할 것 ☐ 필수**(`BOOK.check = 'os'` 이면 checks 없는 noRun 문제는 실패 — 리눅스와 같은 규칙).
- 미니 셸(KB1·KB4)은 **입력을 파이프로 넣어** 검사: `printf '…' | python3 mysh.py` 의 출력 비교.
