## 1. 한 줄로

**「프로그램 여러 개가 CPU 하나 · 메모리 하나 · 디스크 하나를 어떻게 나눠 쓰나」 를 내 우분투 VM 에서 직접 일으켜 보며 배우기.**

- 프로세스를 만들어요(fork · exec).
- 일부러 경쟁 상태를 일으켜 락으로 고쳐요.
- 내 프로그램의 주소 공간과 시스템 콜을 들여다봐요.
- 끝에는 **파이썬으로 작은 셸**을 만들어요.

## 3. 연습 방법 (교과서 원칙 그대로)

### 도구

- 연습은 **사용자의 진짜 도구**로 해요.
  - 리눅스 교과서에서 만든 **VirtualBox 의 우분투 26.04 VM**(스냅샷 「연습장 완성」)
  - **VS Code → Remote - SSH**(리눅스 U13): Windows 의 VS Code 로 VM 안 파일을 고치고, VM 의 터미널에서 실행
- 사이트 안 가짜 운영체제는 만들지 않아요.

### 코드는 파이썬 중심 (9절 Q1)

- 우분투에 처음부터 들어 있는 `python3` 의 모듈을 써요.
  - `os`: `fork` · `exec*` · `wait` · `pipe` · `dup2`
  - `signal` · `threading` · `queue` · `mmap`
- 「파이썬이 숨기는 것」 이 있는 곳만 **C 맛보기**: K14 의 `hello.c` 를 `gcc` 로. `build-essential` 은 리눅스 U7 에서 이미 설치했어요.

### 관찰 도구

- `ps -o pid,ppid,stat,ni,cmd` · `/proc/<pid>/`(status · maps · fd)
- `strace` — 없으면 `sudo apt install strace`
- `/usr/bin/time -v` — 없으면 `sudo apt install time`
- `ls -i` · `stat` · `ln`

### 브라우저 그림 — 눈으로 보기 어려운 것만

- 보조예요. 알고리즘 교과서의 👀 처럼 누를 때만 나와요.
- 세 가지:
  - CPU 스케줄링 **간트 차트**(FCFS · SJF · 라운드 로빈, 슬라이더로 타임 슬라이스)
  - **페이지 교체 표**(FIFO · LRU, 프레임 수 슬라이더 · 페이지 폴트 칸 색칠)
  - **교착 상태 그림**(두 스레드 · 두 락 화살표)
- 수학 교과서의 `core/figure.js` 방식이에요. JS 만으로 즉시 다시 그리고, 파이썬 엔진은 없어요. 새 그림 종류 3개.

### 무거운 실험

- 프로세스 폭탄 방지 · 메모리 많이 쓰기처럼 VM 을 무겁게 만들 수 있는 쪽은 **「먼저 꼭: 스냅샷」**.
- 코드에 상한을 둬요. 예: `for _ in range(5)`.

| 위치 | 제목 |

내용:

- **우분투 연습장**: 이 교과서의 명령 · 코드는 **우분투 VM 안에서** 쳐요.
  - Windows · Git Bash 에는 `fork` · `/proc` 이 없어요.
  - 「리눅스 교과서 UB1 보기 ›」 버튼(돌아오기 있음).
- **스냅샷**: **Machine → Take Snapshot**(리눅스 U4). 프로세스를 많이 만들거나 메모리를 많이 쓰는 실험이 꼬이면 Restore.
- **`fork`**: `while True: os.fork()` 같은 코드는 VM 을 멈추게 해요(프로세스 폭탄).
  - 예제는 늘 **횟수가 정해진 반복**.
  - 자식은 `os._exit(0)` 로 끝내요.
- **스레드와 `fork`**: 스레드가 도는 프로그램에서 `fork` 하면 파이썬이 경고를 내요(3.12~ DeprecationWarning).
  - 이 교과서는 챕터 1(프로세스) · 챕터 2(스레드) 예제를 따로 둬요.
- **`strace`**: `sudo apt install strace`(리눅스 U7 의 apt).

## 5. 목차 (챕터 4 · 레슨 17 + 만들어 보기 4)

- 레슨 id: `K0`~`K16`(Kernel). `O` 는 숫자 0 과 헷갈려서 K 예요.
- 챕터 끝 만들어 보기: `KB1`~`KB4`.
- 쪽 수는 2~4쪽(설명 + 예제), 마지막 쪽은 「🛠 만들어 보기」.
- 「파이썬 검사」 = check_book 이 python3 로 실제로 돌려 봄. ☐ = 내 화면에서 확인.

### 챕터 1 · 프로세스: 프로그램이 살아 움직이는 단위

#### K0 · 운영체제가 하는 일

1. 운영체제 = 프로그램들과 하드웨어 사이의 관리자(그림: 앱들 → 커널 → CPU · 메모리 · 디스크).
2. 프로그램(디스크의 파일) vs 프로세스(실행 중인 것 — 같은 프로그램 여러 개).
3. 커널 모드 / 사용자 모드 맛보기(K14 예고).

- 🛠 같은 `python3` 를 터미널 두 개에서 띄우고 PID 가 다른지 `ps` 로 ☐

#### K1 · `/proc` 으로 프로세스 들여다보기

1. `ps -o pid,ppid,stat,cmd` · 부모 · 자식(PPID) · `pstree`.
2. `/proc/<pid>/status`(State · VmRSS · Threads) · `/proc/self`.
3. 상태 글자 R · S · D · Z · T.

- 🛠 내 파이썬이 `os.getpid()` · `os.getppid()` 를 찍고, `/proc/<pid>/status` 의 `PPid:` 와 같은지(파이썬 검사)

#### K2 · `fork`: 나를 둘로

1. `os.fork()` 는 한 번 불러 **두 번 돌아와요**. 부모는 자식 PID, 자식은 0.
2. 자식은 부모의 복사본. 변수를 바꿔도 부모는 그대로예요(주소 공간 분리, K10 예고).
3. `os.waitpid` · 종료 코드 · 좀비(Z)와 고아.

- 🛠 자식 3개를 만들어 각자 다른 숫자를 계산하고, 부모가 기다려 종료 코드를 모으기(파이썬 검사)

#### K3 · `exec`: 다른 프로그램으로 바꿔 타기

1. `os.execvp("ls", ["ls", "-l"])` — 지금 프로세스가 **다른 프로그램이 돼요**(PID 그대로).
2. `fork` + `exec` + `wait` = 셸이 명령을 실행하는 방법.
3. `subprocess.run` 은 이걸 대신 해 주는 것.

- 🛠 `fork` · `execvp` · `waitpid` 로 `date` 를 실행하고 「종료 코드 0」 출력(파이썬 검사)

#### K4 · 시그널: 프로세스에게 보내는 쪽지

1. `kill -l` · SIGINT(Ctrl+C) · SIGTERM · SIGKILL(못 막음) · SIGSTOP/SIGCONT(Ctrl+Z · `fg`).
2. `signal.signal(signal.SIGINT, 처리 함수)` — Ctrl+C 를 눌러도 「저장하고 끝낼게요」.
3. 리눅스 U10 의 `kill` 은 이것.

- 🛠 Ctrl+C 를 받으면 「정리 중…」 을 찍고 끝나는 프로그램. `os.kill(os.getpid(), signal.SIGINT)` 로 스스로 보내 확인(파이썬 검사)

#### K5 · 파이프와 리다이렉트는 어떻게 만들어지나

1. 파일 디스크립터 0 · 1 · 2(stdin · stdout · stderr — K15 에서 자세히).
2. `os.pipe()` → 읽는 끝 · 쓰는 끝 · `os.dup2` 로 1번을 바꿔 끼우기.
3. `ls \| wc -l` 을 손으로 만들기.

- 🛠 `fork` 두 번 + `pipe` + `dup2` 로 `echo 하나 둘 셋 \| wc -w` 만들기 → `3`(파이썬 검사)

#### KB1 · 🛠 내 미니 셸 1단계

- `mysh$ ` 프롬프트 → 한 줄 읽기 → `fork` · `execvp` · `waitpid` → 종료 코드 표시.
- `cd` 와 `exit` 는 **셸 안에서** 처리해요. 왜 `cd` 는 따로인가: 자식의 폴더만 바뀌니까요.
- Ctrl+C 는 셸이 아니라 실행 중인 명령만 멈추게.
- 검사: 입력 몇 줄을 넣어 출력 비교(파이썬 검사 — `printf 'echo hi\ncd /tmp\npwd\nexit\n' \| python3 mysh.py`) + ☐.

### 챕터 2 · CPU 나눠 쓰기와 동기화

#### K6 · 스케줄링: 누가 먼저 CPU 를 쓰나

1. 문맥 교환 · 준비 큐.
2. FCFS · SJF · 라운드 로빈 — **간트 차트 그림**(슬라이더로 타임 슬라이스) · 평균 대기 시간.
3. 리눅스의 실제 스케줄러(EEVDF, 커널 6.6~)는 「공평하게 + 급한 것 먼저」 · `nice -n 10` · `ps -o ni`.

- 🛠 작업 목록(도착 · 실행 시간)을 받아 FCFS · RR 의 평균 대기 시간 계산(파이썬 검사 — 알고리즘 큐 링크)

#### K7 · 스레드: 한 프로세스 안의 여러 일꾼

1. 프로세스 vs 스레드(주소 공간을 **같이** 씀).
2. `threading.Thread(target=…)` · `start` · `join` · `/proc/<pid>/status` 의 `Threads:`.
3. 파이썬의 GIL 맛보기: 계산은 번갈아, 기다리기(I/O)는 동시에. `time.sleep` 작업 3개가 3초가 아니라 1초.

- 🛠 1초씩 기다리는 작업 5개를 스레드로 → 걸린 시간이 약 1초(파이썬 검사 — 시간은 범위로)

#### K8 · 경쟁 상태와 락

1. 두 스레드가 같은 변수를 「읽고 → 더하고 → 쓰기」.
   - **일부러 틈(`time.sleep(0)`)을 넣어 매번 틀리게** 해요.
   - CPython 에서는 `+=` 만으로는 잘 안 보여서요.
2. `threading.Lock` · `with lock:`.
3. 임계 구역은 짧게.

- 🛠 통장 잔액 100 번 입금이 늘 정확히 맞게 락으로 고치기(파이썬 검사)

#### K9 · 교착 상태와 기다리는 줄

1. 락 두 개를 서로 반대 순서로 → 둘 다 영원히 기다림(**그림**).
   - 네 조건 · 「락은 늘 같은 순서로」 · `lock.acquire(timeout=1)`.
2. 생산자-소비자: `queue.Queue` 가 락 + 기다림을 대신.

- 🛠 생산자 2 · 소비자 2 가 `Queue` 로 일 10개를 빠짐없이 처리(파이썬 검사)

#### KB2 · 🛠 다운로드 대기열

- 가짜 다운로드(`time.sleep`) 12개를 일꾼 스레드 3개가 나눠 처리.
- 진행 줄 「n/12」 를 락으로 · 끝나면 걸린 시간 · Ctrl+C 로 깔끔하게 멈추기(K4).
- 검사: 파이썬 검사 + ☐.

### 챕터 3 · 메모리

#### K10 · 가상 메모리: 프로세스마다 자기만의 주소

1. 주소 공간 = 코드 · 데이터 · 힙 · 스택(그림) · `/proc/self/maps` 읽기.
2. K2 의 「자식이 바꿔도 부모는 그대로」 의 진짜 이유 · 복사는 쓸 때만(copy-on-write).

- 🛠 `/proc/self/maps` 에서 `[heap]` · `[stack]` 줄만 뽑기(파이썬 검사)

#### K11 · 페이지와 페이지 폴트

1. 메모리는 4096바이트 **페이지** 단위(`getconf PAGE_SIZE`) · 페이지 표 · TLB 는 이름만.
2. 처음 만지는 페이지 = 페이지 폴트(`/usr/bin/time -v` 의 「Minor page faults」).
3. RSS(`VmRSS`)는 실제로 만진 만큼만. 큰 `bytearray` 를 만들고 만지며 봐요(구현은 `mmap` — 지금 상태).

- 🛠 100MB 를 만들기만 할 때와 다 만질 때 `VmRSS` 차이(파이썬 검사 — 범위로)

#### K12 · 페이지 교체: 자리가 모자라면 누구를 뺄까

1. 프레임 · FIFO · LRU · 최적(OPT, 비교용) — **페이지 교체 표 그림**(프레임 수 슬라이더 · 폴트 칸 색칠).
2. FIFO 는 프레임을 늘려도 폴트가 늘 수 있음(벨라디의 이상 — 그림으로).
3. 스왑(`free -h` 의 Swap).

- 🛠 참조 문자열을 받아 FIFO · LRU 폴트 수 세기(파이썬 검사 — 알고리즘 딕셔너리 · deque 링크)

#### K13 · 메모리가 모자라면

1. 스왑 · `vmstat 1` 의 si/so.
2. OOM killer(`journalctl -k` 의 「Out of memory」 — 리눅스 U11 링크).
3. 메모리 새는 프로그램을 `/proc/<pid>/status` 로 잡기.

- 🛠 일부러 조금씩 커지는 프로그램을 띄우고 VmRSS 가 느는 것 확인 ☐(상한 있는 코드)

#### KB3 · 🛠 페이지 교체 실험실

- 참조 문자열 · 프레임 수를 받아 FIFO · LRU · OPT 의 폴트 수 표.
- 프레임 1~6 에서 그래프용 숫자 줄 · 그림의 결과와 비교.
- 검사: 파이썬 검사 + ☐.

### 챕터 4 · 시스템 콜과 파일 시스템

#### K14 · 시스템 콜: 커널에게 부탁하기

1. 사용자 모드 → 커널 모드 · `print` 한 줄 아래의 `write(1, …)`.
2. `strace -e trace=write python3 -c 'print("hi")'` · `strace -c` 로 횟수.
3. C 맛보기: `hello.c` 를 `gcc` 로 → 파이썬보다 시스템 콜이 훨씬 적음(T10 어셈블리어 예고).

- 🛠 `strace -c ls` 에서 가장 많이 부른 시스템 콜 이름 ☐
- 🛠 같은 일을 하는 파이썬 · C 의 `write` 횟수 비교 ☐

#### K15 · 파일 디스크립터와 버퍼

1. `open` 하면 받는 번호(0 · 1 · 2 다음 3부터) · `/proc/self/fd` · 닫지 않으면?
2. 버퍼: `print` 가 바로 안 나가는 이유 · `flush` · `os.fsync`(디스크까지).
3. `os.open`/`os.write`(버퍼 없음) vs `open().write`.

- 🛠 `/proc/self/fd` 로 연 파일 수를 세며 `with` 가 닫아 주는지 확인(파이썬 검사)

#### K16 · 파일 시스템: inode 와 링크

1. 이름 ≠ 파일: **inode**(번호 · 크기 · 권한 · 블록 위치) · `ls -i` · `stat`.
2. 하드 링크 `ln`(같은 inode, 링크 수 2) vs 심볼릭 링크 `ln -s`(이름을 가리킴 — 원본 지우면 깨짐).
3. `df -i`(inode 가 바닥나도 「공간 없음」) · 지우기 = 링크 수 줄이기.

- 🛠 하드 링크 · 심볼릭 링크를 만들고 원본을 지운 뒤 각각 읽히는지
  - 설계: bash 검사. 구현: 파이썬(`os.link` · `os.symlink`) 검사 + 명령은 ☐(지금 상태).

#### KB4 · 🛠 미니 셸 완성

- KB1 의 셸에 더해요.
  1. `|` 파이프(K5)
  2. `>` · `>>` 리다이렉트(`dup2`)
  3. `&` 백그라운드 + 끝난 자식 거두기(좀비 방지 — K2)
  4. Ctrl+C 처리(K4)
- 다 하면 리눅스 교과서의 VM 에서 내 셸로 하루 써 봐요.
- 검사: 파이썬 검사(입력 여러 줄 → 출력 비교) + ☐.

> 레슨 수: K0~K16 = 17 + 만들어 보기 4 = **21**. 그림은 K6~K9 에 2개 · K12 에 1개.

## 6. 「만들어 보기」 모양과 검사

- **모양**은 다른 교과서와 같아요.
  - 문장 문제 · **필요한 문법/명령**(실제 코드 — `os.fork()` · `os.execvp(cmd, args)` · `with lock:` · `strace -c`)
  - 입력 예/출력 예 · 예시 답 · (화면에서만 보이는 것은) 확인할 것 ☐
- **자동 검사**: 파이썬 문제는 `check_book` 처럼 **python3 로 진짜 실행**해요.
  - CI 는 ubuntu-latest 라 `os.fork` · `/proc` 이 있어요.
  - 시간 · 메모리처럼 기계마다 다른 값은 출력 예를 **범위로** 봐요. 예: 출력 예 `걸린 시간 1.0초 근처` → 검사는 `0.9~1.6`.

- **자동 검사가 안 되는 것**: `strace` · `vmstat` · `/usr/bin/time -v` · OOM · 여러 터미널.
  - `noRun` + **확인할 것 ☐ 필수**.
  - `BOOK.check = 'os'` 이면 checks 없는 noRun 문제는 실패(리눅스와 같은 규칙).
- **미니 셸(KB1 · KB4)** 은 입력을 파이프로 넣어 검사해요: `printf '…' | python3 mysh.py` 의 출력 비교.
