## 1. 한 줄로

**파이썬 한 줄 아래에서 CPU 가 실제로 하는 일을, 명령 하나하나 직접 써서 본다.** 레지스터에 값을 넣고(`mov`) → 커널에게 글자를 찍어 달라고 하고(`syscall`) → 비교와 점프로 반복을 만들고 → 메모리 · 스택 · 함수를 손으로 다루고 → 마지막엔 C 와 어셈블리를 섞어 「컴파일러가 만든 코드」 를 읽는다. 연습 환경은 **리눅스 교과서의 우분투 VM**(UB1) + **Windows VS Code 의 Remote - SSH**(리눅스 교과서).

## 3. 연습 방법 (교과서 원칙 그대로)

- 설명을 읽고 → **내 우분투 VM** 에서 파일(`hello.asm`)을 만들고 → 터미널에서 빌드 · 실행 → 출력 예와 비교. 사이트는 아무것도 실행하지 않음(예제는 복사 버튼).
- 빌드는 늘 같은 세 줄(시작하기 2 에서 처음, 레슨 2 에서 자세히):
  ```
  nasm -f elf64 hello.asm -o hello.o
  ld hello.o -o hello
  ./hello
  ```
  `printf` 같은 C 라이브러리를 부르거나 C 파일과 섞으면(레슨 13~) `ld` 대신 `gcc -no-pie main.c add.o -o prog`.
- 결과 보기: 처음엔 **종료 코드**(`./prog; echo $?` — 0~255)로 계산 결과를 보고, 레슨 2 부터 `write` 로 글자를 찍고, 레슨 9 의 만들어 보기에서 숫자를 10진 글자로 바꿔 찍는 함수를 만든 뒤로는 그걸 씀. 레슨 13 부터는 `printf` 도.
- 「만들어 보기」 는 3~4개. 예시 답은 CI(GitHub Actions 우분투 x86-64)에서 **진짜로 nasm · ld(또는 gcc)로 빌드하고 실행해** 출력 예와 비교(9절). gdb · 터미널에서 보는 것만 ☐ 「내 화면에서 확인할 것」.

## 6. 「만들어 보기」 모양과 검사 (`BOOK.check = 'asm'`)

- 예시 답(`answer`)은 NASM 소스. 파일이 여럿이면 줄 하나로 나눔: `; ==== 파일: add.asm ====` · `// ==== 파일: main.c ====`(이 줄 아래가 그 파일). 나누는 줄이 없으면 `main.asm` 하나.
- `tools/asm_book_run.py` 가 임시 폴더에서 `.asm` 은 `nasm -f elf64`, `.c` 는 `gcc -c -O0` 하고, **`.c` 가 있거나 `global main` 이면 `gcc -no-pie`**, 아니면 `ld` 로 링크해 실행. stdin 은 `io.input`.
- 출력 예 = 터미널에 보이는 그대로. 종료 코드를 보는 문제는 `echoExit: true` → 실행 출력 바로 뒤에 `echo $?` 의 숫자를 붙여 비교(진짜 터미널처럼, 출력이 줄바꿈 없이 끝나면 숫자가 그 줄에 붙음).
- 레슨 예제(`example.code`)도 같은 방법으로 빌드 · 실행(에러가 나면 실패, `example.stdin` · `example.echoExit` 사용). 본문의 「실행하면 `값`」 주장도 그 출력과 대조(check_book ⑤).
- gdb · objdump · 설치처럼 화면에서 보는 것은 `noRun: true` + `checks` ☐(필수). `example.shell` 은 보여 주기만.

## 7. 시작하기 · 도감 · 허브

- 시작하기 2쪽: **1. 준비물**(리눅스 교과서 UB1 의 VM · Remote - SSH · `sudo apt install nasm gdb build-essential` · `nasm -v` · 연습 폴더 `~/asm`) **2. 쓰는 법**(VS Code 에서 `hello.asm` 저장 → VS Code 터미널(= VM 의 bash)에서 빌드 세 줄 → 출력 예와 비교, 「NASM」 확장은 선택 — 색칠만).
- 도감: 쪽 제목이 실제 명령(`mov` · `syscall` · `cmp` · `push` · `call` …)이라 저절로. `builtins` 로 **시스템 콜 표**(read 0 · write 1 · exit 60)와 **레지스터 표**를 따로.
- 허브: 「공용」 칸 카드 「어셈블리어」(운영체제 옆), 글리프 `asm`, 레슨 수는 채울 때마다.

## 9. 정한 것과 이유 (기술적 선택 — Claude)

| 무엇 | 정한 것 | 이유 |
| --- | --- | --- |
| 레슨 id | `R0`~`R16` · `RB1`~`RB4`, 코스 id `asm` | 다른 코스 글자(L·A·M·T·V·G·S·W·H·U·K)와 안 겹침, R = Register |
| 연습 환경 | 리눅스 교과서의 우분투 VM + VS Code Remote - SSH | 사용자 결정(우분투) · 이미 만든 연습장. Windows 에서 x86-64 리눅스 실행 파일은 안 돌아감 |
| 시작점 | `_start` + `ld`(챕터 0~2), `main` + `gcc -no-pie`(챕터 3~4) | 처음엔 C 라이브러리 없이 「커널에게 직접」 이 가장 덜 숨김. `printf` 가 필요할 때 gcc 로. `-no-pie` 는 `call printf` 를 그대로 쓰게(PIE 의 `wrt ..plt` 는 R15 에서 이름만) |
| 결과 보기 | 종료 코드(`echo $?`) → `write` → 숫자 출력 함수 → `printf` | 숫자 출력이 어셈블리에서 의외로 어려워서, 쉬운 것부터 단계로. 종료 코드는 0~255 로 잘리는 것도 같이 배움 |
| 문법 | NASM 인텔 문법, AT&T 는 R0 · R15 에서 읽기만 | 사용자 결정 · `gcc -S` · `objdump` 의 기본은 AT&T 라 읽는 법은 필요 |
| 검사 | CI 우분투 러너에서 nasm · ld · gcc 로 진짜 빌드 · 실행(`tools/asm_book_run.py`), gdb 는 ☐ | 다른 교과서처럼 「예시 답은 진짜로 돈다」 를 지키기. GitHub Actions 러너가 x86-64 우분투라 가능(nasm 은 apt 로 설치) |
| 브라우저 그림 | 없음(본문 표 · `<pre>` 글 그림) | 레지스터 · 스택 그림은 글 상자로 충분, 진짜 값은 gdb 로 보는 게 이 교과서의 핵심 |
| 끝 프로젝트 | 숫자 출력(RB2) → 함수 모음(RB3) → C + 어셈블리 단어 세기(RB4) | 앞 만들어 보기의 코드가 다음 챕터의 재료가 되게(RB2 의 숫자 출력 → RB3 의 `print_int`) |
