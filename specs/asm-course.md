## 1. 한 줄로

**파이썬 한 줄 아래에서 CPU 가 실제로 하는 일을, 명령 하나하나 직접 써서 본다.**

1. 레지스터에 값을 넣고(`mov`)
2. 커널에게 글자를 찍어 달라고 하고(`syscall`)
3. 비교와 점프로 반복을 만들고
4. 메모리 · 스택 · 함수를 손으로 다루고
5. 마지막엔 C 와 어셈블리를 섞어 「컴파일러가 만든 코드」 를 읽어요.

연습 환경은 **리눅스 교과서의 우분투 VM**(UB1) + **Windows VS Code 의 Remote - SSH**(리눅스 교과서)예요.

## 2. 다른 교과서와의 경계

| 주제 | 이미 있는 교과서 | **어셈블리어 교과서** |
| --- | --- | --- |
| VM · 우분투 · apt · 터미널 · VS Code Remote - SSH | ✅ 리눅스 U0~U14 | 다시 안 가르침. 시작하기에서 「리눅스 교과서 UB1 · Remote - SSH」 로 보냄 |
| 시스템 콜이 무엇이고 언제 일어나나(`strace`) · 파일 디스크립터 0·1·2 | ✅ 운영체제 K14 · K15 | `syscall` 명령으로 **직접 부르는 법**(번호 · 레지스터). 개념은 링크 |
| 2진수 · 16진수 · 비트 연산 · 2의 보수 | ✅ 알고리즘(비트 연산) · 수학 교과서 | 레지스터에서 **눈으로 보기**만. 개념은 링크 |
| 프로세스 메모리 지도(코드 · 데이터 · 힙 · 스택) | ✅ 운영체제 K10 | `section .data` · `.bss` · `.text` 와 스택이 그 자리라는 연결만 |
| C 문법 | — (C 교과서 없음) | 레슨 13~16 에 필요한 만큼만(`int main` · `printf` · 함수 선언). C 를 가르치는 교과서가 아님 |
| CPU 의 구조(파이프라인 · 캐시) · 명령어 집합 설계 | CS 교과서(설계 땐 예정) | 「이런 게 있다」 한두 줄. 개념은 CS 교과서 |

- 정정: 처음 표에는 리눅스가 「U0~U17」 로 적혀 있었어요. 리눅스 교과서 레슨 id 는 U0~U14 예요(데이터 확인).

## 3. 연습 방법 (교과서 원칙 그대로)

- 설명을 읽고 → **내 우분투 VM** 에서 파일(`hello.asm`)을 만들고 → 터미널에서 빌드 · 실행 → 출력 예와 비교.
- 사이트는 아무것도 실행하지 않아요. 예제는 복사 버튼.

### 빌드

늘 같은 세 줄이에요. 시작하기 2 에서 처음, 레슨 2 에서 자세히 다뤄요.

```
nasm -f elf64 hello.asm -o hello.o
ld hello.o -o hello
./hello
```

- `printf` 같은 C 라이브러리를 부르거나 C 파일과 섞으면(레슨 13~) `ld` 대신 `gcc -no-pie main.c add.o -o prog`.

### 결과 보기 — 쉬운 것부터 단계로

1. 처음엔 **종료 코드**로 계산 결과를 봐요: `./prog; echo $?`(0~255).
2. 레슨 2 부터 `write` 로 글자를 찍어요.
3. 레슨 9 의 만들어 보기에서 숫자를 10진 글자로 바꿔 찍는 함수를 만든 뒤로는 그걸 써요.
4. 레슨 13 부터는 `printf` 도 써요.

### 만들어 보기

- 레슨마다 3~4개.
- 예시 답은 CI(GitHub Actions 우분투 x86-64)에서 **진짜로 nasm · ld(또는 gcc)로 빌드하고 실행해** 출력 예와 비교해요(9절).
- gdb · 터미널에서 보는 것만 ☐ 「내 화면에서 확인할 것」.

## 4. 「먼저 꼭」 경고 (prereq)

| 위치 | 제목 |
| --- | --- |
| 목차 챕터 0 위 · 레슨 0 1쪽 · 모든 만들어 보기 | 먼저 꼭! 리눅스 교과서의 우분투 연습장(UB1)이 있어야 해요 |
| 시작하기 1 · 레슨 2 1쪽 | nasm 설치 |
| 레슨 2 · 레슨 6 | 끝나지 않는 프로그램 · 세그멘테이션 폴트는 VM 이 망가진 게 아니에요 |
| 레슨 13 1쪽 | `printf` 를 부르기 전에 스택을 16바이트에 맞추기 |

내용:

- **우분투 연습장**: 이 교과서의 명령은 전부 **우분투 VM**(x86-64) 안에서 쳐요.
  - Windows · Mac(Apple 칩)에서는 같은 코드가 안 돌아요.
  - VS Code 는 리눅스 교과서의 Remote - SSH 로 VM 폴더를 열어서 써요.
- **nasm 설치**: `sudo apt install nasm gdb build-essential` 한 번. 확인: `nasm -v` · `gcc --version`.
- **세그멘테이션 폴트 · 끝나지 않는 프로그램**:
  - `exit` 시스템 콜을 빼먹으면 `Segmentation fault (core dumped)`.
  - 반복의 끝 조건이 틀리면 안 끝나요 → `Ctrl`+`C`.
  - 둘 다 그 프로그램만 멈춰요.
- **스택 정렬**: `main` 에서 `push rbp` 한 번(레슨 12 의 규약). 안 맞추면 어떤 컴퓨터에서는 바로 세그멘테이션 폴트.

## 5. 목차 (챕터 5 · 레슨 17 + 만들어 보기 4 = 21)

- 레슨 id: `R0`~`R16`(Register). 만들어 보기: `RB1`~`RB4`.
- 레슨 번호(n)는 0~16.

### 챕터 0 · 시작

#### R0 · 어셈블리어란

1. 파이썬 → 바이트코드 / C → 기계어. CPU 는 기계어(바이트)만 알아요.
   - 어셈블리어 = 기계어를 사람이 읽는 이름으로.
   - 예: `mov rax, 60` ↔ NASM 은 `b8 3c 00 00 00`. `objdump` 에는 `mov eax,0x3c` 로 보여요.
   - 7바이트 꼴 `48 c7 c0 …` 은 다른 어셈블러의 모양이에요.
2. 어셈블러(NASM) · 링커(ld) · 실행 파일(ELF) 흐름 그림(글).
3. 왜 배우나: 디버거 · 성능 · 보안 · 「컴퓨터가 진짜 하는 일」.
4. 이 교과서의 약속: x86-64 · 인텔 문법(`mov 받는쪽, 주는쪽`) · 우분투. AT&T 문법(`%rax`)은 읽을 줄만.

- 🛠 「종료 코드 42 로 끝나는 프로그램」 그대로 쳐 보기 · `objdump -d` 로 바이트 보기 ☐

### 챕터 1 · 첫 어셈블리 (레지스터 · 시스템 콜 · 계산)

#### R1 · 레지스터와 `mov`

1. 레지스터 = CPU 안의 변수 16개(`rax rbx rcx rdx rsi rdi rbp rsp r8~r15`) · 64비트.
2. `mov rax, 5` · `mov rbx, rax` · 숫자 쓰는 법(10진 · `0x` 16진 · `0b` 2진).
3. 같은 상자의 작은 이름 `eax` · `ax` · `al`(그림: 64/32/16/8). 32비트에 쓰면 위가 0 이 돼요.
4. 결과를 보는 첫 방법: `rdi` 에 넣고 `exit` → `echo $?`.

- 🛠 종료 코드로 값 보기 · 레지스터 옮기기 · 큰 수가 256 으로 잘리는 것 보기

#### R2 · 첫 프로그램: `write` 와 `exit` 시스템 콜

1. 파일 모양: `section .data` · `section .text` · `global _start` · `_start:` · 주석 `;`.
2. `db "안녕", 10` · 길이 `equ $ - msg`.
3. 시스템 콜 = 번호는 `rax`, 인자는 `rdi rsi rdx`, 그리고 `syscall`. write=1 · exit=60 표(운영체제 K14 링크).
4. 빌드 세 줄 · 에러 읽기.
   - `nasm` 에러는 줄 번호를 알려 줘요.
   - `ld: warning: cannot find entry symbol _start` 는 경고라 실행 파일은 생겨요.
   - exit 을 빼면 세그멘테이션 폴트.

- 🛠 Hello · 두 줄 출력 · 종료 코드 3 으로 끝내기

#### R3 · 계산: `add` · `sub` · `imul` · `idiv`

1. `add rax, rbx` · `sub` · `inc` · `dec` · `neg`.
2. `imul rax, rbx` · `idiv` 는 `rdx:rax` 를 나눠 몫 `rax` 나머지 `rdx`(`cqo` 먼저).
3. 넘침(오버플로): 64비트를 넘으면 잘려요. 음수는 2의 보수(종료 코드로 보면 255 = -1).

- 🛠 사칙연산 결과를 종료 코드로 · 섭씨 → 화씨 · 몫과 나머지

#### R4 · 비트 연산: `and` · `or` · `xor` · `shl` · `shr`

1. `and` 로 고르기 · `or` 로 켜기 · `xor` 로 뒤집기 · `xor rax, rax` = 0.
2. `shl` = ×2 · `shr` = ÷2 · `sar`(음수).
3. 홀짝 `and rax, 1` · 대문자 ↔ 소문자(`xor al, 0x20`, 아스키 표). 알고리즘 교과서 비트 연산 링크.

- 🛠 홀짝 · 2의 거듭제곱 · 글자 하나 대문자로

#### RB1 · 🛠 계산 결과 알림

- 두 수의 합 · 차 · 곱을 차례로 계산해요. 합은 종료 코드로.
- 결과에 따라 고정 메시지(「100 넘음」 등). 분기는 아직이니 계산만으로.
- 챕터 1 묶기. 검사: 자동 + ☐.

### 챕터 2 · 흐름과 메모리

#### R5 · 비교와 점프: `cmp` · `jmp` · `je` · `jl` …

1. 라벨과 `jmp`.
2. `cmp a, b` 는 빼 보고 결과는 버리고 **플래그**(ZF · SF · CF · OF)만 남겨요.
3. 조건 점프 표: `je jne jl jle jg jge`(부호 있음) · `jb ja`(부호 없음).
4. if / else 모양 만들기.

- 🛠 큰 수 고르기(종료 코드) · 짝수면 「짝수」 출력 · 세 갈래

#### R6 · 반복 만들기

1. 카운터 + `dec` + `jnz` · `cmp` + `jl` 로 while 모양.
2. 1~n 합 · 거듭제곱.
3. `loop` 명령(rcx)은 있다는 것만 · 끝나지 않는 반복 경고.

- 🛠 1~100 합 · 별 n 개 출력 · 팩토리얼

#### R7 · 메모리와 주소: `[ ]`

1. `section .data` 의 `db dw dd dq` · `.bss` 의 `resb resq`.
2. `mov rax, [num]`(읽기) · `mov [num], rax`(쓰기) · 크기 `byte` `qword`.
3. `lea rsi, [msg]` = 주소 자체 · 주소 vs 값(그림).
4. `default rel` 한 줄(왜 필요한지 한 줄).

- 🛠 변수 두 개 바꾸기 · 메모리에 결과 저장 후 출력

#### R8 · 배열과 문자열

1. 배열 `dq 3, 1, 4` · `[arr + rcx*8]`(주소 계산 모양).
2. 합 · 최댓값.
3. 문자열은 바이트 배열 · 0 으로 끝나는 문자열 · 길이 세기.
4. 한 글자씩 바꾸기(대문자로).

- 🛠 배열 합 · 최댓값 · 문자열 길이 · 대문자로

#### R9 · 입력 받기: `read` 시스템 콜

1. `read`(번호 0) · `rdi=0` stdin · 버퍼 `resb 64` · 돌려준 길이 `rax`.
2. 받은 글자 그대로 되돌려 찍기(echo).
3. 글자 숫자 → 정수(`'0'` 빼기 × 10) · 정수 → 10진 글자(나눗셈 반복, 거꾸로).

- 🛠 이름 받아 인사 · 두 자리 수 더하기

#### RB2 · 🛠 숫자를 출력하는 프로그램

- 정수를 10진 글자로 바꿔 `write` 하는 코드 + 한 줄 입력을 거꾸로 뒤집어 출력.
- 챕터 2 묶기. 이 코드가 챕터 3 의 `print_int` 함수가 돼요. 검사: 자동.

### 챕터 3 · 스택과 함수

#### R10 · 스택: `push` · `pop` · `rsp`

1. 스택 = 아래로 자라는 메모리 · `rsp` 가 꼭대기(그림).
2. `push rax` = `sub rsp, 8` + 저장 · `pop`.
3. 값 잠깐 맡기기 · 뒤집기에 쓰기(글자를 push 했다가 pop).

- 🛠 세 값 거꾸로 · 스택으로 문자열 뒤집기

#### R11 · 함수: `call` 과 `ret`

1. `call f` = 돌아올 주소를 push + 점프 · `ret` = pop 해서 점프.
2. 인자는 레지스터로 · 결과는 `rax`.
3. 함수 안에서 레지스터를 망가뜨리면? → push/pop 으로 지키기.
4. 재귀 맛보기(팩토리얼).

- 🛠 `print_int` 함수로 만들기 · `strlen` · 재귀 팩토리얼

#### R12 · 호출 규약(System V AMD64)

1. 인자 순서 `rdi rsi rdx rcx r8 r9` · 결과 `rax`.
2. 부르는 쪽이 지킬 것 / 불리는 쪽이 지킬 것(`rbx rbp r12~r15` 보존).
3. 스택 프레임 `push rbp` · `mov rbp, rsp` · 지역 변수 `sub rsp, 16` · `leave`.
4. 스택 16바이트 정렬(왜 · 어떻게).

- 🛠 인자 3개 함수 · 지역 변수 쓰는 함수 · 규약 어긴 코드 고치기

#### R13 · C 라이브러리 부르기: `printf`

1. `extern printf` · `global main` · `gcc -no-pie` 로 링크(왜 `_start` 대신 `main` 인지).
2. `printf("%d\n", x)` = `rdi` 에 형식 주소 · `rsi` 에 값 · `xor eax, eax`(가변 인자 규칙).
3. `puts` · `strlen` · 돌아올 땐 `ret`(종료 코드 = `rax`).
4. 스택 정렬 경고(4절).

- 🛠 구구단 한 단 · 배열 출력 · 문자열 길이 printf

#### RB3 · 🛠 내 함수 모음

- `print_int` · `strlen` · `to_upper` · `max_of(arr, n)` 를 규약대로 만들고 `main` 에서 차례로 불러요.
- 챕터 3 묶기. 검사: 자동.

### 챕터 4 · C 와 어셈블리 사이

#### R14 · C 에서 어셈블리 함수 부르기

1. `main.c` + `add.asm` 두 파일 · C 쪽 선언 `long add(long a, long b);` · asm 쪽 `global add`.
2. `gcc -no-pie main.c add.o -o prog` · 타입과 레지스터 크기(`int` = `edi`, `long` = `rdi`, 포인터).
3. 배열 · 문자열을 넘기기(포인터 = 주소).

- 🛠 두 수 더하기 · 배열 합 · 문자열 거꾸로(C 가 출력)

#### R15 · C 가 어떻게 바뀌나: `gcc -S` · `objdump -d`

1. `gcc -S -O0 -masm=intel -fno-asynchronous-unwind-tables` 로 내 C 를 어셈블리로.
2. `if` · `for` · 함수가 어떤 모양이 되나(지금까지 배운 것과 짝 짓기).
3. `-O2` 로 바뀌는 것(반복이 사라지기도) · `objdump -d -M intel` 로 실행 파일 읽기 · AT&T 문법 읽는 법 한 쪽.

- 🛠 ☐ 내 C 를 어셈블리로 · 자동: 읽은 어셈블리와 같은 일을 하는 C 쓰기

#### R16 · `gdb` 로 한 줄씩

1. `nasm -g -F dwarf` · `gdb ./prog` · `layout asm` / `layout regs`.
2. `break _start` · `run` · `stepi` · `info registers rax` · `x/s &msg` · `x/4gx $rsp`.
3. 세그멘테이션 폴트 찾기(`bt`) · 무엇을 보면 되나.

- 🛠 ☐ 레지스터 따라가기 · ☐ 폴트 난 줄 찾기 · 자동: 버그 고치기

## 6. 「만들어 보기」 모양과 검사 (`BOOK.check = 'asm'`)

- **예시 답(`answer`)** 은 NASM 소스예요.
  - 파일이 여럿이면 줄 하나로 나눠요: `; ==== 파일: add.asm ====` · `// ==== 파일: main.c ====`(이 줄 아래가 그 파일).
  - 나누는 줄이 없으면 `main.asm` 하나.
- **`tools/asm_book_run.py`** 가 임시 폴더에서 빌드해 실행해요.
  - `.asm` 은 `nasm -f elf64`, `.c` 는 `gcc -c -O0`.
  - **`.c` 가 있거나 `global main` 이면 `gcc -no-pie`**, 아니면 `ld` 로 링크.
  - stdin 은 `io.input`.
- **출력 예** = 터미널에 보이는 그대로.
  - 종료 코드를 보는 문제는 `echoExit: true`. 실행 출력 바로 뒤에 `echo $?` 의 숫자를 붙여 비교해요.
  - 진짜 터미널처럼, 출력이 줄바꿈 없이 끝나면 숫자가 그 줄에 붙어요.
- **레슨 예제**(`example.code`)도 같은 방법으로 빌드 · 실행해요.
  - 에러가 나면 실패. `example.stdin` · `example.echoExit` 를 써요.
  - 본문의 「실행하면 `값`」 주장도 그 출력과 대조해요(check_book ⑤).
- gdb · objdump · 설치처럼 화면에서 보는 것은 `noRun: true` + `checks` ☐(필수). `example.shell` 은 보여 주기만.

## 9. 정한 것과 이유 (기술적 선택 — Claude)

| 무엇 | 정한 것 | 이유 |
| --- | --- | --- |
| 레슨 id | `R0`~`R16` · `RB1`~`RB4`, 코스 id `asm` | 다른 코스 글자(L·A·M·T·V·G·S·W·H·U·K)와 안 겹침, R = Register |
| 연습 환경 | 리눅스 교과서의 우분투 VM + VS Code Remote - SSH | 사용자 결정(우분투) · 이미 만든 연습장. Windows 에서 x86-64 리눅스 실행 파일은 안 돌아감 |
| 시작점 | 챕터 0~2: `_start` + `ld`. 챕터 3~4: `main` + `gcc -no-pie` | 아래 목록 |
| 결과 보기 | 종료 코드(`echo $?`) → `write` → 숫자 출력 함수 → `printf` | 숫자 출력이 어셈블리에서 의외로 어려워서, 쉬운 것부터 단계로. 종료 코드가 0~255 로 잘리는 것도 같이 배움 |
| 문법 | NASM 인텔 문법, AT&T 는 R0 · R15 에서 읽기만 | 사용자 결정. `gcc -S` · `objdump` 의 기본은 AT&T 라 읽는 법은 필요 |
| 검사 | CI 우분투 러너에서 nasm · ld · gcc 로 진짜 빌드 · 실행(`tools/asm_book_run.py`), gdb 는 ☐ | 「예시 답은 진짜로 돈다」 를 지키기. GitHub Actions 러너가 x86-64 우분투라 가능(nasm 은 apt 로 설치) |
| 브라우저 그림 | 없음(본문 표 · `<pre>` 글 그림) | 레지스터 · 스택 그림은 글 상자로 충분. 진짜 값은 gdb 로 보는 게 이 교과서의 핵심 |
| 끝 프로젝트 | 숫자 출력(RB2) → 함수 모음(RB3) → C + 어셈블리 단어 세기(RB4) | 앞 만들어 보기의 코드가 다음 챕터의 재료가 되게(RB2 의 숫자 출력 → RB3 의 `print_int`) |

시작점을 둘로 나눈 이유:

- 처음엔 C 라이브러리 없이 「커널에게 직접」 이 가장 덜 숨겨요.
- `printf` 가 필요할 때 gcc 로 바꿔요.
- `-no-pie` 는 `call printf` 를 그대로 쓰게 해요. PIE 의 `wrt ..plt` 는 R15 에서 이름만.
