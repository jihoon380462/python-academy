### 3-D. 에이전트 주장 중 반증된 것 (이 보고서에서 뺌)

- 챕터 8 에이전트: 「`B8` 문제 1 정답의 `split(" ", 1)` 을 챕터 1~8 어디서도 안 가르침 = 막힘」. **틀림.** 챕터 3 의 `L9` 쪽 5 가 `split(" ", 1)` 설명과 예제를 가르치고, 칩이 가리키는 `L9/5` 가 맞는 쪽이에요(본문 추출 120~131행에서 확인함). 같은 에이전트의 「`L29` 문제 1 · `L9B` 의 구분자 `split` 도 `L9` 쪽 5 에 없다」 도 같은 근거라 뺐어요.
- 챕터 5 에이전트가 먼저 알려 준 오탐: 「`any([s = 50 for …])`」 같은 깨진 코드는 추출 도구가 `<` 를 지운 것(`any([s < 60 …])` 가 원본, 확인함).
- 제 초기 스캔 오탐: 「이 앱 · 채점」 11곳은 `content.js` 원문에만 있고 `book.js` 의 `rep` 로 화면에서 바뀜. `rep` 를 적용한 화면 본문에서는 `이 앱` · `채점` · `입력창` 이 **0곳**(확인함).

## 4. 반복되는 패턴 (일관성 · 가독성 · 정보 밀도)

모두 챕터 에이전트 보고예요. 몇 곳은 제가 원문으로 확인했어요.

1. **문제 제목 형식이 챕터마다 달라요.**
   - 「— 출력 예측」 / 「— 출력 맞히기」 / 「(출력 예측)」 / 「, 출력 맞히기 (출력 예측)」(「출력 예측」이 두 번)이 섞임.
   - 에러 읽기: 「… — 에러 읽기」 / 「에러 읽기 — …」 / 「~이 안 돼요」 / 콜론.
   - 🏠 표시가 일부 문제에만 있음.
   - 쪽 제목도 `:` / `—` / `·` / 구분 없음이 섞임.
2. **용어 혼용**: 목록/리스트 · 열쇠/키(`L36` · `L37` · `B9` 가 딕셔너리 key 를 「열쇠」 라고 부름, 에이전트 확인) · 시험/테스트 · default 값/기본값 · args/argv · 인자/매개변수 · 행/열 vs 줄/칸 · 「수량자 · 문자 클래스」(`L20` 제목) vs 「개수 기호 · 대괄호 안 글자」(본문).
3. **난이도가 갑자기 뛰는 곳**: `L12C` 문제 1(첫 문제가 얕은 복사) · `L11C` 문제 4 · `B3` 문제 4 · `L18B` 문제 2 · `L18C` 문제 2~4 · `B5` 문제 6(RPG) · `B6` · `X5` 문제 3 · `L19C` 순서 · `B4` 문제 1 · `L15E` 문제 3 · `B8` 문제 4 · `B9` 문제 6(튜플 패턴 `match`)이 꼽혔어요.
4. **본문이 가르친 걸 「예제 코드」가 안 돌림**: `L9` 쪽 5(`partition`) · `L12C` 쪽 2(얕은 복사) · `L9C` 쪽 2.

## 6. 고치는 순서 제안 (고치지 않음 · 사용자 판단)

1. **틀린 정보 3-A**(12건). 한두 줄씩이라 한 PR 로 가능.
2. **3-B 의 칩 · 안 배운 문법**. 칩 글자를 정답 모양에 맞추고, 빠진 한 줄을 본문에 넣기.
3. **폰 코드 블록 · 에러 상자 잘림**: 에러 · 경고 상자만이라도 줄바꿈 허용(`white-space: pre-wrap`), 코드 블록에는 「더 있음」 표시.
4. **자동 검사 보강**: 「정답이 쓰는 문법이 칩이 가리키는 쪽에 있는가」 를 `check_book` 에 추가(3-B 가 모두 이 종류). 쓰지 않는 칩 · 문제 번호 · 줄 수 말(「여섯 줄」 · 「네 문제」)과 실제 개수 비교도 후보.
5. **QA 지시서에 준비 단계** `pip install pytest playwright` 추가.
6. 한 쪽 과밀(3-C), 일관성(4절)은 다음 읽기 검수에서 쪽 단위로 정리. 「쪽을 더하거나 지우지 마요」(지시서 5절) 제약이 있어서 쪽을 나누려면 맨 끝에만 새 쪽을 붙이는 방식을 따져야 해요.
