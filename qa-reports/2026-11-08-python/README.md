## 0. 읽는 법

- **쪽 번호**: 칩 · `check_book` 과 같이 `레슨id/번호` 로 적고 번호는 **0부터** 세요(`L13/4` = L13 의 다섯 번째 쪽). 화면 배지는 번호 + 1 이에요. 글에 「쪽 4」 처럼 쓴 곳도 같은 0부터 번호예요.
- **레슨 번호**: `L13(화면 25)` 처럼 id 와 화면 번호를 같이 적었어요.
- **확인 정도**
  - 「직접 확인」: 실행하거나 원문과 대조해서 확인
  - 「의심」: 읽어서 그렇게 보임
  - 「QA 방이 확인」: 읽기 담당 에이전트가 올린 항목을 QA 방이 원문 · 실행으로 다시 대조
  - 이 표시가 없는 「직접 확인」 은 에이전트가 확인한 것
- **심각도**: 「막힘」(따라 하다 막히거나 잘못 배움) · 「헷갈림」 · 「사소」
- 「만들어 보기 n」 은 레슨 마지막 쪽의 문제 번호(화면 배지와 같은 번호)예요.

## 4. 여러 챕터에 걸친 패턴 (개발 방이 한 번에 손볼 만한 것)

1. **「필요한 문법」 칩이 가장 많이 어긋나요.**
   - 여러 문장을 공백으로 이은 모양: `L1` 만들어 보기 2, `L6` 만들어 보기 1·2·4 (`i = 0   while total <= 100:   i += 1`), `L7B` 만들어 보기 4 등
   - 가리키는 쪽에 그 모양이 없음: `range(len(items))` → `L5/3`(`L9C` 만들어 보기 4, `B2` 만들어 보기 5), `sum(d.values())` → `L10B/2`, `max(리스트)` · `min(…)` 를 값 두 개로 쓰는 문제 → `L7C/2`(`L32` 만들어 보기 4, `B8` 만들어 보기 5), `if row["행사"]:` → `L4/2`(`X10` 만들어 보기 3), `split("\n")` → `L20/4`(`L20B` 만들어 보기 3)
   - 다른 문제 전용 숫자 · 코드가 섞임: `L6` 의 `total <= 100`, `L5` 만들어 보기 2·3 의 `range(1, 6)` ↔ 실제 답(`range(1, 11)` · `range(1, 7)`), `L15B` 만들어 보기 3 의 칩 `max` ↔ 답 `min`
   - **캡스톤 만들어 보기 3 의 칩이 3~4개뿐**: `X1` · `X2` · `X3` · `X4` · `X5` · `X6` 등. 예시 답에 필요한 조각(`sorted(key=int)`, `best = None`, 튜플 key 정렬, `set(...)` …)이 칩에 없음
   - `check_book` 의 칩 검사(`needWords`)는 칩 코드의 낱말이 가리키는 쪽에 **하나라도** 있으면 통과해서(`words.some`) 이런 어긋남을 못 잡아요. 호출 모양(예: `range(len(`)이 대상 쪽에 있는지로 강화하면 잡을 수 있어요.
2. **접힌 「💡 더 알아보기」 에 기대는 곳**: `X2/4` 의 csv 빈 줄 막는 법, `L35/2` 의 `__getitem__` 이유. 접힘은 배운 것으로 안 치므로 핵심은 본문으로.
3. **본문 코드가 그대로는 안 도는 곳**: `L18B/5`(`s = 50`), `L21` 쪽 6 · 7(`is_even` · `test_odd` 정의 없음), `L39/3`(`fee()` · `import pytest` 없음), `L40/1·2`(`import asyncio` · `asyncio.run` 없음), `L16/3`(`import random` 없음), `X16/2`(import 없음), `X13/5`(`root` · `label` · `greet` 먼저 있음 안내 없음). 챕터 5 를 읽은 에이전트가 그 챕터의 본문 코드 블록 전부를 `ast.parse` 로 훑었을 때 문법 오류는 `L18B/5` 하나뿐이었어요(다른 챕터는 이 검사를 안 했어요). 같은 검사를 `check_book` 에 넣으면 같은 종류를 막을 수 있어요.
4. **같은 문장 반복 · 쪽 주제와 다른 내용**: 디버거 사용법 문단이 `L2/3`(변수 레슨 한가운데)과 `L22/4` 에 거의 그대로 반복, `L21/5` 의 `tempfile` 단락, `X3`·`X4` 의 「`2026-1-5` … 자세히는 L19」 가 세 쪽에 반복.
5. **한 쪽에 몰린 설명(정보 밀도 · 구조화)**: `L9/5`(split · partition · 언패킹 · `_`), `L7C/4`(remove · del · pop · 빈 리스트 거짓), `L16C/0`, `L20B/0`, `L39/0`, 만들어 보기 문제 글의 한 불릿에 명령 다섯 개(`X8` 만들어 보기 3), 한 문단 절차 ①②③(`L27/3`, `L22/0`).
6. **쪽 안 번호 · 이름 검사가 못 잡는 옛 표현**: 「몸풀기」 · 「N 문제」(실제와 다른 개수) · 쪽 제목 속 `L7C` 같은 id. `check_book` ⑬ 은 제목 번호와 「위 · 앞 · 다음 문제」 만 봐요.

### 챕터 2 (L5~L8C · B2, 화면 6~13·복습)

#### 헷갈림
2-1. L6(화면 7) 만들어 보기 1·2·4 · 「필요한 문법」 칩 `i = 0   while total <= 100:   i += 1` — [직접 확인(데이터)] 문제 4(100 을 넘는 순간) 전용 모양인데 문제 1(1~5 세기), 문제 2(카운트다운)에도 똑같이 붙어 있음. 세 문장이 공백 세 칸으로 한 줄에 이어진 모양이고 L6/1 의 실제 예제(`i = 3`, `while i > 0`)와도 다름. 제안: 문제마다 맞는 칩으로.

## 챕터 3 (읽기 담당 에이전트 보고 + QA 방 대조) — 레슨 L9~L12C, B3 (12개 전부 읽음)

대조 결과: 항목 1·2·4·7·8·9 = QA 방이 원문/실행으로 확인(아래 표시). 에이전트도 읽기 자료 변환 착시 두 가지(`&#91;`→`[`, B3 만들어 보기 2 의 `.- ` 는 `<ul>`)를 스스로 걸러 제외함.
에이전트가 돌려 맞았다고 한 것: 슬라이싱, partition, split, find, `[:-1]`, f-string 서식, 집합 연산, 정렬, copy(), round, B3-1 에러 두 종류 — 쪽 코드 주석과 해설에서 실제와 다른 숫자·출력은 없음(항목 1 의 가짜 에러 문구 제외). 말투·금지어·문제 번호 참조·레슨 번호 참조 문제 없음(쪽 제목 `L7C` 하나만 예외).

### 헷갈림
1. L11(화면 19) 쪽 0 · 튜플 — 주석 `point[0] = 9   # TypeError: 튜플은 바꿀 수 없어요` . 실제: `TypeError("'tuple' object does not support item assignment")`. L9 쪽 1 은 진짜 메시지를 보여 줘 서로 다름. 제안: 실제 메시지로 바꾸고 뜻 한 줄. [직접 확인(QA 방이 실행)]
2. L12(22) 쪽 3 · round — 「자릿수를 빼면 정수로 반올림해요. 단, 딱 `.5` 이면 짝수 쪽으로」 가 짝수 쪽 규칙이 정수 반올림에만 있는 것처럼 읽힘. 실제 `round(87.25,1)`→87.2, `f"{87.25:.1f}"`→87.2, `round(0.125,2)`→0.12, `round(2.675,2)`→2.67. L12 만들어 보기 2(평균)에서 87.25 같은 값을 만나면 87.3 기대. L9C 쪽 0 은 `.2f` 를 「셋째 자리에서 반올림」 만. 제안: 규칙을 자릿수 준 경우까지 넓히고 「소수는 컴퓨터 숫자 오차로 어긋날 수도」 한 줄. [직접 확인(QA 방이 실행)]
3. L9(14) 쪽 5 · split — 한 쪽에 split() → split("-") → split(" ", 1) → partition → 세 변수 언패킹 → `_` 관례 → 다른 챕터 문제 예고까지(본문 약 25줄, 제목은 「s.split(): 단어로 쪼개기」). partition 설명 자체는 단계가 갖춰짐(무엇을 돌려주나·split(" ",1)과 차이·빈칸 없을 때 `('목록','','')`·실제 출력). 그 코드는 읽기 전용 블록이고 「예제 실행」 칸은 `input().split()` 예제라 partition 을 직접 못 돌림. 마지막 문장 `「🏠 메모장 앱」 문제([[레슨:B5]] 안에 있어요)는 partition 을 써요` 는 5개 챕터 뒤 문제를 가리킴. [직접 확인(원문 대조) / 학생이 막히는지는 의심]
4. L12C(24) 쪽 0 · sort() — `sort()`/`sorted()` 차이는 있으나 `nums = nums.sort()` → None 단골 실수 없음(L8B 쪽 3 에서 None 은 배움). `nums=[3,1,2]; print(nums.sort())` → None. [직접 확인(QA 방이 실행)]
5. L12C(24) 쪽 1 · sort(key=…) — 챕터 안 처음 나오는 `lambda` 를 「지금은 f → f의 가격으로 읽으면 돼요」 로 넘김(정식은 L18 화면 39). 그런데 만들어 보기 3 은 `key=lambda s: s["score"]` 를 직접 써야 함. 두 번째 문단 한 개에 「sorted에도 key」·「딕셔너리를 값 기준으로」·「items() 쌍=튜플」·「kv[0]/kv[1]」·「L11 point[0]」 줄줄이, `kv` 설명 없음. [의심(코드·출력은 실행해 같음)]
6. L9B(15) 쪽 2 · 찾은 자리로 자르기 — 「못 찾음 → at = -1 → `email[:at]` = `email[:-1]` → mins」 흐름은 단계대로 맞고 출력도 같음(최근 고친 곳). 빈 곳 둘: (a) `[:-1]` 이 「맨 끝 한 글자 앞까지」 라는 건 말로만, L9 쪽 1 에 끝 번호가 음수인 예(`s[:-1]`) 없고 `s[-3:]`·`s[-1]` 만. (b) 같은 at=-1 이면 `email[at + 1:]` 은 `email[0:]`, 통째로 `minsu`. 이 쪽은 앞쪽 슬라이스만 따라가는데 B3 만들어 보기 1·L9B 만들어 보기 3 은 뒤쪽도 씀. 제안: `print(email[at + 1:])  # minsu` 한 줄, `"minsu"[:-1]` 나란히. [직접 확인(실행)]
7. L9(14) 쪽 1 · 쪽 제목 「s[a:b]: 문자열도 리스트처럼 잘라요(레슨 L7C 복습)」  — 제목은 순수 글자라 `L7C` 가 그대로 보임(화면 번호는 10). 본문의 같은 곳은 토큰이라 「레슨 10」 으로 바뀜. [직접 확인(QA 방이 grep)]
8. L9C(16) 만들어 보기 4 · 칩 — `for i in range(len(items)): → L5/3 (번호로 두 리스트를 같이)` 의 L5/3 은 `range(시작, 끝)` 쪽, `range(len(리스트))` 는 거기 없음(ch00~ch02 에서 L8B 쪽 3 함수 예제에만). 챕터 2 B2 의 같은 칩을 따라온 듯: B2 만들어 보기 5 에도 `for i in range(len(items)): → L5/3` 이 있음(QA 방이 ch02 에서 확인). [직접 확인]
9. B3 만들어 보기 2 · 칩 `sum(d.values()) → L10B/2 (값 전부 더하기)` — L10B/2 에 sum 모양 없음(반복 `for v in price.values(): total += v` 만), L7C/2 는 `sum(리스트)` 만. 반복으로도 풀려 막히진 않음. [직접 확인(QA 방이 L10B/2 grep: sum 없음)]
10.
