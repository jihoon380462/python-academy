## 2. 상세

### P1-01 입력 중인 코드가 저장되지 않음 (상)
- **증상**: 코드를 치다가 새로고침하면 starter 로 돌아간다. 폰은 앱 전환·메모리 부족으로 탭이 다시 불러와지는 일이 흔하다. 파일 업로드가 있는 프로젝트(X1~X6)나 길게 치는 문제에서는 큰 손실.
- **재현**: 폰 폭 → 파이썬 `UI.go('problem',{pid:'L2P1',lessonId:'L2'})` → 「작업」 탭 → 코드 칸 전체 선택 후 `x = 5⏎print(x)` 입력 → 6초 기다리고 blur → 새로고침 → 홈의 「이어서 풀기」 → 「작업」 → 코드 칸이 `name = "파이썬"` (starter).
- **근거**: 6초 뒤·blur 뒤 모두 `localStorage` 4개 키(`academy.profile/course.python/works/tutor.python`)에 입력한 문자열이 없음. `Store.prob('L2P1')` 에도 코드 필드 없음(`{"status":"none"}`). 스크립트 `scripts/draft2.py`, 결과 `raw/ux.json`.
- **제안**: 문제별 초안(draft)을 입력 디바운스로 저장하고 문제를 다시 열 때 복원(「원래대로」·「이 문제 초기화」는 starter 로). 클리어하면 초안 삭제.
- 참고: 이 항목은 CodeMirror 가 아니라 앱 저장 로직 문제라 실제 사이트에서도 같을 가능성이 높지만, CodeMirror 의 `onChange` 연결은 이 환경에서 확인 못 했다.

### P1-02 화면 주소가 안 바뀌고 뒤로가기가 앱 밖으로 나감 (중)
- **증상**: 홈→레슨→문제로 이동해도 `location.hash` 가 항상 `""`, `history.length` 가 늘지 않는다. 브라우저/안드로이드 뒤로가기 한 번에 사이트 밖(`about:blank`)으로 나가고, 새로고침하면 어디 있었든 홈으로 간다. HANDOFF 에는 딥링크 `#problem/ID`·`#lesson/ID`·`#settings` 가 있다고 되어 있어(입력만 지원) 이동 때 해시를 쓰지 않는 것이 어긋남.
- **재현**: `UI.go('home')` → `UI.go('lesson',{lessonId:'L2'})` → `UI.go('problem',…)` → `history.back()` 두 번 → 앱 밖. `raw/ux.json` 의 `back1`, `back2`, `hash_on_problem`.
- **제안**: `UI.go` 가 `history.pushState`(또는 해시)를 쓰고 `popstate` 에서 `UI.back` 처럼 이전 화면으로. 폰 뒤로가기가 가장 자주 쓰는 조작이라 우선순위 높음.

### P1-03 오답 제출 후 결과가 화면 밖 (중, 폰)
- **증상**: 「작업」 탭에서 오답을 제출하면 스크롤이 안 움직인다(`scrollY` 0). 「어디가 다를까」·실패 사유는 코드 칸 아래 y≈1287px 에 있어(뷰포트 844) 아무 변화도 안 보인다. 정답일 때만 아래로 내려감(`scrollY` 282).
- **재현**: 폰 → `L1P1` → 「작업」 → 코드 칸에 `print("x")` → ✔ 제출하기 → `scrollY === 0`, `#pvResult` top 1286.9. 스크린샷 `shots/04_wrong_submit_result_offscreen.jpg`.
- **제안**: 제출 뒤 실패 시에도 `#pvTests`(또는 실패한 첫 테스트)로 스크롤하거나, 제출 버튼 옆에 「0/2 통과 · 자세히 ▾」 한 줄을 눈에 보이게.

### P1-05 입력 없는 코드 문제 34개는 출력만 print 해도 클리어 (중, 설계)
- **증상**: 테스트에 `input` 이 없고 출력이 한 가지뿐인 문제는 `import sys; sys.stdout.write("정답 출력")` 만으로 클리어된다. 지문이 반복(for/while)·함수(def)·f-string·딕셔너리·정렬·클래스를 쓰라고 해도 쓰지 않아도 통과. 정답을 꼬아 쓴 코드(`exec`로 감싸기, 줄 끝 공백, CRLF, 빈 줄 추가)는 전부 정상 통과 — 채점이 출력만 보기 때문.
- **재현**: 폰 → 해당 문제 → 코드 칸 `import sys⏎sys.stdout.write("안녕, 파이썬!\n")` → 제출 → 클리어. 전체 결과는 `raw/adversarial_grading.csv` (변형 `hardcode_t0`, 기대 fail, 실제 pass 34건). 스크립트 `scripts/adv.py`.
- **영향**: 반복·함수 같은 핵심 기능을 안 쓰고 넘어가도 진도가 나간다. 무료 교육·초보자용이라 의도일 수 있어 **「중」** 으로 둔다 — 결정은 사용자/기획 몫.
- **제안(선택지)**: ① 입력이 있는 테스트를 하나 더 만들어 하드코딩 막기(`{{n}}` vary 활용), ② 「코드 구조 검사」(예: `for` 가 있어야 함) 유형을 core 에 추가, ③ 그대로 두고 지문에서 「직접 계산해서 적지 말고」만 강조(L3P1 처럼).
- 통과하는 34개(지문 요약 포함)는 `hardcode_passable.md`.
- 참고: 이 34개는 테스트가 1개뿐이라 화면에 「테스트 2 (숨김)」 이 같은 내용으로 뜬다(마지막 1개 숨김 규칙이 의미 없음).

### P1-06 게임 요소가 꺼져 있는데 뱃지 토스트가 뜸 (중)

### P1-07 고대비 「높게」에서 선택된 칩 대비 2.66:1 (중)
- **증상**: 설정 → 고대비 「높게」일 때 선택된 칩(`.seg .on`)이 흰 글자(`rgb(255,255,255)`) / 배경 `rgb(90,160,255)` = 대비 2.66:1(작은 글자 4.5 기준 미달). 고대비인데 보통 모드보다 선택 상태가 흐리다. 같은 칩이 문제 화면의 「설명」 탭, 일일 목표 「5문제」 등에도 쓰임.
- **재현**: 설정 → 고대비 → 높게 → 테마 「다크」 칩. `raw/audit_python.json` 의 `mobile-dark-hc/*` (`contrast` 목록). 스크린샷 `shots/03_highcontrast_selected_chip.jpg`.
- **제안**: 고대비에서는 선택 칩 배경을 더 진한 파랑(또는 글자를 검정)으로.

### P1-08 터미널 시뮬레이터의 `ls` 파이프·`-1` 동작 (중)
- **증상**: 진짜 셸은 `ls` 가 파이프로 연결되면(그리고 `ls -1`) 한 줄에 하나씩 내보낸다. 시뮬레이터는 항상 한 줄에 쭉 붙여서 낸다.
  - `ls | wc -l` → `1` (진짜: 항목 수, 홈에서는 `3`)
  - `ls -1` → `memo.txt  notes/  projects/` 한 줄
  - `ls | head -n 1` → 전체 한 줄
  - `ls | grep html` 은 정상.
- **재현**: 터미널·Git `T0P1` → 「작업」 → `ls | wc -l`. 스크립트 `scripts/tg2.py`.
- **영향**: 초보자가 진짜 터미널에서 다른 결과를 보고 혼란. 코스 목적(가상 터미널로 연습)과 어긋남.
- **제안**: `ls` 구현에서 stdout 이 파이프/`-1` 이면 줄 단위로 출력.

### P1-18 약한 테스트 후보 (하)
한 글자 변이 165개 중 20개가 통과(살아남음). 대부분은 같은 동작이 되는 변이(동치)라 제외했고(`"utf-8"`→`"utf+8"`(파이썬이 같은 코덱으로 처리), 최대값 찾기의 `>`→`>=`, `guess < secret` 뒤에 `==` 분기가 있어 `<=` 도 동일 등), **진짜 약해 보이는 것 2개**만 남긴다:
- **X5P1**(일기장 통계): `while cur <= last:` → `while cur < last:` 가 통과 → 마지막 날이 빠지는 버그를 테스트 7개가 못 잡는다.
- **B5P1**(텍스트 RPG 전투): `if mon.hp <= 0:` → `if mon.hp < 0:` 가 통과 → 체력이 정확히 0일 때를 테스트가 안 다룸.
나머지 18건의 판단 과정은 `raw/adversarial_grading.csv` 의 `mut:` 행과 `scripts/adv.py` 의 변이 목록으로 재현.

### P1-19 `2>/dev/null` (하) / P1-20 지문 요약 잘림 (하)

## 3. 정상 확인 (회귀 방지용)
- **채점 변형 930건**(파이썬 코드 문제 96개 × 변형 9~10개, `raw/adversarial_grading.csv`): 빈 코드·주석만 → 전부 실패. 정답을 꼰 코드(`exec` 감싸기·줄 끝 공백·CRLF·빈 줄·`pass` 끼우기) → 96개 전부 통과. 한 글자 변이 165개 중 112개 실패·33개 시간 초과(무한 루프)·20개 통과(위 P1-18).
- **빈칸 문제 26개**(선택지 전부 시도, `raw/fill.json`): 선언된 정답만 통과.
- **억지로 부수기 25건**(`raw/break.json`): 문법 오류·전각 기호·탭/공백 섞임·NameError·0 나누기·무한 루프·무한 print·500만 글자 출력·20만 줄 출력·재귀·`input()` 입력 없음·`import os`·파일 열기·`exit()`·이모지·널 문자·4000글자 한 줄·괄호 300겹·`exec`·언더스코어 속성 — 앱이 죽지 않고 한국어 안내를 내고 이어서 정답이 다시 돌아감. 무한 루프는 약 10초 뒤 안내, 실행 중에는 「⏹ 멈추기」가 보임.
- **웹 미션(HTML)**: `h1` 대문자·공백·불완전 태그·`script` 로 만든 h1 은 통과(DOM 검사), 주석·textarea 안·h2·글자만·빈 코드는 실패, 무한 JS 를 넣어도 앱은 살아 있음.

- **다른 코스 첫 화면**(알고·수학·터미널·SQL·웹, 폰): 가로 넘침 0, 콘솔 에러 0. 수학 첫 노드 그림(슬라이더·「나머지」 강조)은 폰에서 읽기 좋음(`shots/09_…` 참고용).
- **폭**: 폰 390·320·가로 모드 844×390 에서 홈·문제 화면 가로 넘침 0.
