## 방식 (사용자 지시: 직접 플레이 + 다각도, 수정 금지)
- 폰 폭 390px(터치·`is_mobile`)로 신규 학습자처럼 홈 → 온보딩 → 레슨 0 → 문제를 눌러 보며 진행, 이후 PC 폭(1280)도 같이 측정.
- 코드 문제는 실제 화면의 「✔ 제출하기」로 변형 코드를 넣어 채점 결과를 봤다: 빈 코드·주석만·정답 출력 하드코딩·정답을 꼰 코드·한 글자 변이·문법 오류·무한 루프·대량 출력·재귀 등.
- 화면은 DOM 자동 측정(가로 넘침·글자 크기·터치 영역·글자 대비·잘림)과 스크린샷으로 읽기 쉬움·시인성을 봤고, 폰에서 새로고침·뒤로가기·키보드 올라온 상태·가로 모드·320px 폭의 사용성을 직접 해 봤다.
- 새 코스(터미널·Git·웹)는 직접 명령·코드를 넣어 플레이, SQL 은 엔진이 막혀 화면까지만.

## 환경 한계 (결과를 읽을 때 꼭 알아 둘 것)
- 작업 환경에서 `github.io`·jsdelivr·unpkg 가 막혀 있어 **실제 배포 사이트가 아니라 저장소를 로컬 서버로 띄워** 플레이했다(main `675ba3d` = v2.8.10).
- Pyodide 는 `tools/e2e_submit/server.py` 의 흉내(진짜 CPython 하위 프로세스)로 대신했다. 그래서 시간·메모리·`time.sleep` 같은 실행기 의존 동작은 진짜와 다를 수 있어 보고에서 뺐다.
- CodeMirror 가 안 불러져 편집기는 textarea 폴백이다(자동완성·붙여넣기 막기 등 확인 못 함).
- 사용자는 폰에서 보고 있어서 Claude in Chrome 확장은 쓸 수 없었다.
